# cc-start: intake

> `CC` = `C:/Users/Bulzart/.claude/create-clips` · `PY` = `C:/Users/Bulzart/AppData/Local/Programs/Python/Python312/python.exe` · `T` = `"$PY" "$CC/scripts/cc.py"` (every call prints one JSON object on its last line; run through PowerShell) · `RUN` = the run folder.

## Read now
- `CC/README.md` (the contract: the run layout, rec time, the chunk table, the chunk reports). Nothing else yet.

## Steps
1. **The mode, the captions choice and (streamer mode) the videos choice, and with shorts their level, come first, and the user picks them** (nothing here guesses the mode or the videos). `$ARGUMENTS` may carry `mode=streamer` or `mode=game`, `captions=on` or `captions=off`, `only=long`, `only=both` or `only=shorts`, and `shorts=concentrated` or `shorts=normal`: what is given is not asked. A run whose `state.json` already holds a `mode` (a resume) keeps it, and keeps its `captions` (a run made before the option existed has none: that means `on`), its `only` (a run made before the question existed has none: that means `both`) and its `shorts_level` (a run made before the question existed has none: the planner then judges the number of shorts as before).
   Otherwise, before anything else, ask with AskUserQuestion, **all the missing questions in ONE call** (one dialog, headers `Mode`, `Captions` and `Videos`; `Videos` only when the mode is streamer or is asked in the same call, and never in game mode):
   - `Mode`: "Which kind of clipping is this run?" with two options:
     - **Streamer clipping**: "A person is the show (jokes, hype, arguments, chat, lingo). Research of the streamer, their audience and the topic; short-form videos (up to 3 minutes) and long-form videos, with zooms and sound effects (and captions if you pick them)."
     - **Game clipping**: "A match is the show (BLAST Premier CS2, a Dota 2 game, Valorant, League). Research of the game, the event and the teams; every round or fight decided (full, trimmed, a flash or skipped); long condensed-match videos only, one video and one CapCut project per game (a recording with several different matches gives each its own), no shorts, no sound effects; sponsor stretches are cut."
   - `Captions`: "Should the videos have captions?" with two options:
     - **Captions (Recommended)**: "Every second of speech is captioned in every video (names fixed from the research), in the look of Loupe video 04: Luckiest Guy, upper case, the spoken word on a rounded colour box, in a small to normal size for phones; the box colour is matched to each video. The standing default."
     - **No captions**: "The same cuts, zooms and blurs, nothing typed on the picture: no caption track is made. A slur spoken aloud stays audible, so the plan cuts around such lines."
   - `Videos` (streamer mode only; the answer is ignored when the user picks Game clipping, which makes long videos only): "Which videos should this run make?" with two options, **no default and no "Recommended" mark: the user picks**:
     - **Long videos only**: "Long-form videos, each one a whole watch (usually about 25 minutes to an hour) split where the stream's own stories end so nothing is left half told: straight runs of the stream and pickups. The agents decide how much of the stream is worth it: hours of videos from a great night, half an hour from a quiet one, none from a dull one. No shorts."
     - **Long videos + shorts**: "The long-form videos (whole watches of about 25 minutes to an hour) and short-form ones too (Shorts, TikTok, Reels: always 9:16, up to 3 minutes each; you pick how many next), planned together and built at the same time."
   **The shorts level** (the user, 2026-11-14; a follow-up, because it depends on the `Videos` answer and so cannot be in the same call): when the run will make shorts (streamer mode, `only` is `both` or `shorts`) and `shorts=` was not given, then, as soon as the first dialog is answered, ask ONE more question with AskUserQuestion, header `Shorts`: "How many shorts should this run make?" with two options, **no default and no "Recommended" mark: the user picks**:
     - **Concentrated**: "Only the one, two or three best shorts: the most highlighted pieces of the content, the ones with the most potential, each given the most care. Fewer if fewer are worth it."
     - **Normal**: "About 5 to 10 shorts across the stream's good moments. Fewer if the stream does not have that many worth making: nothing is made just to reach a number."
   The level is a range the user chose, never a quota (`cc-plan` makes fewer when fewer are worth it). Not asked when no shorts are made (`only=long`, game mode).
   The answers are the mode, the captions setting, the videos choice and (with shorts) the shorts level; "Other" text that names one of the options is taken as that one (`shorts only` is taken as `only=shorts`), anything else: ask once more. If the questions cannot be asked (a non-interactive run), the mode must come as `mode=streamer` or `mode=game` (stop and say so otherwise), `captions` is `on` unless `captions=off` was passed, in streamer mode `only` must come as an argument (stop and say so otherwise), and when shorts are made `shorts=concentrated` or `shorts=normal` must come as an argument too (stop and say so otherwise).
   `T state --run RUN set mode=streamer captions=on only=both shorts_level=normal` (or `game`, `off`, `long`, `concentrated`; game mode records `only=long` without asking, and `shorts_level` is left out when no shorts are made) once the run is known (step 3), and `game="..."` when the user gave it.
2. **Arguments** (`$ARGUMENTS`): the run folder (a path, or a session name under `runs_root`), then optional `only=long|both|shorts` (streamer mode: the answer to the `Videos` question, so it is not asked when given; game mode makes long videos only and `only=shorts` is refused in one line), `shorts=concentrated|normal` (streamer mode: the answer to the `Shorts` question, so it is not asked when given; ignored when no shorts are made), `notes="..."` (what the user knows: the guest, the topic, what they want), `streamer="Name"`, `game="Counter-Strike 2"`, and, optional and never asked, the user's own pick of the caption box colour: `captions_color="#E02B3A"`.
   The caption font is not an option: it is always Luckiest Guy (the user, 2026-11-13: "always use the same font family as they used in that video"; edit-craft.md "The look"). Without `captions_color` the production agents pick the box colour per video to match its appearance; with it every video of the run uses the user's colour wherever its EDL leaves it open.
   No run given: `T status` lists the runs; with exactly one run that has chunks, take it, otherwise report the list and stop (the only other time to ask).
3. **The run**: `T status --run <arg>` (stages per chunk, the report column, free space, totals). Take what is there: a chunk with stage `failed` or `pending` is listed and skipped; `T chunks --run RUN` is the table.
   The recording may still be growing (a watcher running): `T state --run RUN get recording` and `get stream_ended` say whether the recorder has ended it (the stream ended, it was stopped, a limit was reached: `reason`); when it has not ended, the chunk table at this moment is the run for this pass.
   `T status` also prints `ready` (the recording ended, every chunk processed, every report settled: the watcher then showed the user a Windows notification) and, when it is false, `why_not`: say in one line what is still running; it is information, not a stop, the rule above stands.
   Record the chunks used (`T state --run RUN set snapshot_chunks=<n>`) and use only those chunks. No processed chunk at all: stop and say what to run (`T watch`).
4. **Facts to hold**: channel, date, number of chunks and total length, the title and category changes (`00-inventory/stream-meta.json`), the source quality (`probe.json` of a chunk), gaps, the spoken language (the `Spoken language` line of `stream.md`, `language` in `T status`: `CC/reference/language.md`), the ad-marked chunks (`T status` prints `ad_marked`; `T blocks` lists the batches: the recorder skips nothing, ad or not ad, and Twitch's marker is a fact the mining agents judge, see `CC/reference/moment-mining.md`), free space on the drive.
   Read `RUN/00-inventory/stream.md` once (the table of numbers per chunk).
5. **Folders**: `RUN/20-analysis/blocks`, `RUN/40-briefs`, `RUN/60-outputs`, `RUN/deliverables` exist (`New-Item -ItemType Directory -Force`); game mode also `RUN/20-analysis/hud`.
6. **Start everything that does not wait for anything else, together, in ONE message** (speed: nothing below needs another's result):
   - **The one research agent**, in the background (Agent tool, general-purpose, no `model` argument, web only), briefed from `CC/reference/research-agent.md`: its contract for this mode, the run, the channel, the date, the spoken language, the stream's title and category from `stream-meta.json`, the user's `notes`, `streamer` or `game`, its output `RUN/20-analysis/research.md`, its budget (`config.json -> agents.research_calls` tool calls, a short note, not a deep research). It is the only research agent of the command (`config.json -> agents.research_max`). `T state --run RUN set research.status=running`.
     The recon, the HUD map and the scan of the next phases run while it works; `cc-profile` / `cc-profile-game` collect its note.
   - **The chunk reports** (made while the chunks were downloaded: a headless Haiku session per chunk reads its sheets, audio numbers, transcript and chat and writes `RUN/10-media/Cnnnn/report.md`; observations only, `CC/reference/reporter.md`): the `reports` counts of `T status` say how many are `ok`, `missing`, `stale`, `failed`, `running`.
     Complete what is not there: `T report --run RUN --parallel 4` (every chunk without a current report; the sessions run side by side, about a minute each; it prints the count, the cost and anything that failed). A chunk whose report cannot be made (no claude CLI, a failure twice) is listed: the analysis reads its raw data instead.
   - **Streamer mode:** `T sfx-scan --run RUN` catalogues the sound-effects folder (`30-assets/sfx.md`; it fails plainly when the folder is missing); game mode has no sound effects and skips it.
   - `T doctor` must show ffmpeg and ffprobe working; game mode also needs the screen reader (it shows whether `rapidocr_onnxruntime` loads; when it does not, say so: the analysis then works from the casters' words, the reports and the sheets).
   CapCut running is noted (the build needs it closed), not a blocker yet.
7. **Size the work**: `T config get agents` shows `scan_chunks_streamer` (10) and `scan_chunks_game` (8): the analysis makes one block per that many chunks (the agents read the reports, so a block is large), at least `scan_min_blocks` (2) blocks so that even a short recording is read by agents side by side, at most `scan_max` (6) agents at a time. A 4-hour stream is about 8 blocks; a short stream is two.
   The user's `notes`, `streamer`, `only` and `captions_color` go into `state.json` (`T state --run RUN set notes="..." only=long captions_color="#E02B3A"`). `shorts_level` is the answer to the `Shorts` question (`concentrated` or `normal`; `cc-plan` reads it). `only` is the answer to the `Videos` question: `long` plans and builds no short, `both` plans both kinds, `shorts` (an argument only) no long video; `cc-plan` reads it.
8. `T state --run RUN set stage=started next_skill=cc-profile` (streamer) or `next_skill=cc-profile-game` (game).

## Never
- Never move, rename, delete or rewrite a chunk, a sheet, a transcript or a report. The run's media is read-only for the whole command.
- Never guess the mode and never change it later: the user picked it; the same for the videos choice (long only, or long plus shorts) and the shorts level. Never ask anything but the mode, the captions choice, the videos choice (streamer mode), the shorts level (only when shorts are made) and, when it is missing, the run.
- Never start a second research agent, never a research wave.

## Hand-off
Invoke Skill `cc-profile` (streamer mode) or `cc-profile-game` (game mode).
