# Building the CapCut project (the production agent's recipe): ONE command, one composition

`CS` = `C:/Users/Bulzart/.claude/create-static` · `PY` = `C:/Users/Bulzart/AppData/Local/Programs/Python/Python312/python.exe` · `T` = `"$PY" "$CS/scripts/cs.py"` (run through PowerShell; each call prints one JSON object on its last line) · `RUN` = the run folder.
Every video of a Static run, in every format, is built by ONE command, `T capcut-build` (item 39; the user, 2026-11-13: "use capcut composition for everything if possible for faster delivery"). It builds the whole project from the video's timeline in a single `capcut compile`, writes what compile has no operation for in one pass over the project's files, repairs the project and reads it back: one answer with a `problems` list.
Measured on a real 12.7-minute video (128 stills, 4,413 caption texts, 17 labels, 6 joins, narration and bed): 23 s for the whole build. The same project made by the single commands one after another took about 3 minutes, and the two projects were compared segment by segment: every still, move, join, label, font, box field and entrance equal; the caption texts' times equal to the microsecond (the SRT route rounds them to the millisecond).
Never build a project tool by tool (the CapCut MCP, `capcut add-video`, one command per feature): the composition is the only route.

## Facts about this PC's CapCut that shape the build
- CapCut 9.7 Free unless the run's CapCut plan is Pro (`state.json → capcut_plan`; a free-plan project that uses a Pro option will not export). CapCut and capcut-cli writes refuse while CapCut runs: **CapCut must be closed**. If it is open the build says so and changes nothing (exit 3): a blocker notice, never a question.
- The stills and the two long audio files (the narration, the bed) are used **in place**: compile builds the draft on a 350 KB black placeholder (`RUN/30-assets/compose/placeholder.mp4`) and the build points every still and audio clip at its real file afterwards (path, name, size, length), in all three copies of the timeline (`draft_content.json`, `draft_info.json`, `template-2.tmp`). C: has little free space; a still is never copied into a draft. Effect overlays, drawing clips and sound effects are small and are copied into the draft by compile, as before.
- The draft starts from `CS/data/compose-template`, an empty draft that carries this PC's CapCut 9.7 version markers (capcut-cli's own `auto` would use its bundled CapCut 6.5.0 skeleton). Never pass `--template auto`.
- CapCut 9.7 ignores `UNIFORM_SCALE` keyframes: moves are written as KFTypeScaleX with the clip's uniform scale on plus KFTypePositionX/Y. Never `capcut_add_keyframe` for a move.
- Chroma key and screen blend: capcut-cli's do not play on this PC; green screens and black backgrounds go in as alpha files (`static §9`, §7). The build decides each effect's way from `CS/data/capcut-catalogue.json` and refuses what the catalogue does not show playing.
- `capcut compile` adds the project to CapCut's SHARED project index (root_meta_info.json), a read-modify-write: the build holds the machine-wide store lock (`config.json → capcut.store_lock`, the file every toolkit that writes the index takes) around compile and around the repair. A build that waits for it says nothing; it only takes a few seconds longer.
- Never `capcut lint --fix`, `--force-write`, `capcut_transcribe`, `capcut_add_captions`, `capcut_clear_captions` or a save with force (item 39).
- The caption font and the labels' font are the plan's files (`captions.font_file`, `labels_style.font_file`), in the library's `fonts/` folder so the project keeps finding them (`static §7` "Fonts"); the build lists any character the font cannot draw (`caption_font.font_missing_glyphs`) as a problem.

## Steps
1. **The plan is current.** `T slideshow plan --run RUN --video NN [--format <tag>]` has written the timeline (`40-briefs/video-NN-timeline[-<tag>].json`) and the captions (`60-outputs/video-NN[/<tag>]/captions.srt`), its `undecided` is empty and every drawing is rendered and current (`T draw list`). The video's brief block S4 (what was decided: moves, joins, labels, effects, the box's colour and why) was written before the build (`static §13`).
2. **Look before you build** (free, CapCut may be open): `T capcut-build --run RUN --video NN [--format <tag>] --spec-only` writes `60-outputs/video-NN[/<tag>]/compose-spec.json` and answers with the plan's facts: the number of images, tracks, items and operations, the joins, the caption look it will use (`word-box` or `plain`, and whether the video's language takes the word box), the labels, the effects and the ones it refuses (`effects_refused`). Anything that stops the build stops it here with exit 2 and a plain sentence (a missing still, a join or an entrance the catalogue does not show drawn, a caption line wider than 92 % of the frame, words that do not line up with the narration's, an undecided style key).
3. **Build**: `T capcut-build --run RUN --video NN [--format <tag>] [--captions auto|word-box|plain|none]` (the project name is made for you: `DD_Mon_YYYY_vNN`, `-<tag>` for an extra format, `-2`, `-3` when the folder exists; `--name` chooses one; `--store` another drafts folder). `--captions auto` follows the plan (the word box when `captions.word_box` is set and the language takes it). Its answer:
   - `ok` and `problems`: a list of plain sentences; `ok` is true only when it is empty. A problem is a fact that disagrees with the plan: the main track's clip count, a clip not at its image's start and span, an end time that differs from the timeline's, clips that do not start where the one before ends, a move without keyframes, a join the draft does not hold, the narration or the bed not where the timeline says, an effect that was refused or is not on its track, a text count that differs from the composition's, texts without their font or entrance, a media file missing on disk, media with no entry in the project's media list, a `capcut lint` error, characters the font cannot draw, a failed step.
   - `draft` (the full path), `name`, `export`; `seconds` and `seconds_by_part` (`plan_and_spec`, `compile`, `write_pass`, `repair_and_read_back`).
   - `compose`: the counts that went into the single `capcut compile` (`images`, `tracks`, `items`, `operations`, `transitions`), `effects.written` and `effects.refused`, `labels` (`count`, `tracks`, `on_moving_images`), `captions` (`mode`, `texts`, `tracks`, `boxed_texts`, `geometry`, `language`, `word_box_supported`), `media_retargeted` (stills and audio pointed at their real files), `moves_keyed`, `fonts_set`, `entrances_cloned`, `copies_written` (the three copies of the timeline), `media_pool_entries_dropped`; and `extras_error_then_composed_bare` with `older_steps` only when compile refused the joins or the texts: then the clips, the audio and the effects were composed alone and the rest was written by the toolkit's older commands one by one; read those steps.
   - `read_back` (facts read from the finished project): `main_clips` against `planned_images`, `main_end_s` against `planned_s`, `spans_off`, `joins_not_contiguous` (0), `moves_keyed` against `moves_planned`, `transitions_in_draft` against `transitions_planned`, `audio` (narration and bed: present, start, volume), `texts` against `texts_planned`, `texts_off`, `fonts_off` (0), `entrances` against `entrances_planned`, `effects_missing`, `media_missing` (`[]`), `media_without_entry` (`[]`), `draft_mb`, `lint` (`errors` must be 0; `by_code` lists the rest: one `info:media-outside-draft` per still and audio file is expected because they stay in place, and in the word-box look many `warning:caption-too-fast` because a word's text can show for 0.1 to 0.5 s).
   - `caption_font` (the file, `font_missing_glyphs`, `font_covers`), `cleanup_mb` (capcut-cli's undo snapshots and `*.bak` copies, removed after a good build: they were 100 MB for one video) and a `note` of what no tool here can see.
   A `problems` entry is yours to fix or to report, never to ignore. Fix in the plan or the stills, then `T slideshow plan` again, then build again under a new `--name`; a failed build leaves its draft folder: name it in the brief and never use it.
4. **Look at it** (the read-back cannot): nothing here renders the project (no local render, `static §7`), so how CapCut draws it is the user's first look: name in the brief block S4 what only playing shows (the caption box's corners and place, the entrance, a join's look, a keyed overlay's edges, a drawing over its picture, a right-to-left or joined script) and tell the user to open the project, check the first frame, a move, a join and a caption once, and export at the format's export size, 30 fps.
5. **Record** the build's answer in the brief (block S4: the facts of `compose` and `read_back`, the project's name and full path, any `problems` and how they were settled), then `cs-record`.

## When something goes wrong
- CapCut is running (exit 3): close it, run the build again. It changed nothing.
- It stops with exit 2 and a sentence (no timeline, a missing still, a refused join or entrance, a caption line too wide, the language cannot take the word box: `word_box_supported: false`): fix the cause named (a join or entrance the catalogue does not show drawn is changed in the plan, never in the build; for a language the word box cannot place build again with `--captions plain` and name it in the brief) and run it again. Nothing was built.
- `capcut compile failed`: the error text is capcut-cli's. The half-made folder the build left is yours to remove only by its exact path; never delete a CapCut project you did not make in this build.
- `big media files were copied into the draft` or `items of the composition have no clip`: the draft is wrong; delete that one draft folder by its exact path and build again under a new `--name`.
- A `capcut lint` error, `media_without_entry` or a `fonts_off` count: build again after fixing the file or the font named; never `capcut lint --fix`.
- Never leave a half-built project that looks finished: if the build cannot be completed, the record says what is missing and the video's `result.json` has `status` `failed` or `blocked`.

## What stays in the plan, not the build
Every look, move, join, effect, label, font and box colour is the plan's (item 25: scripts gather, agents decide): the build writes the timeline's values and reads the project back; it never picks an amount, a join, a font or a colour, and it never changes the plan. An option the catalogue does not show drawn (or Pro on a free plan) is refused in `problems` or at `--spec-only`, and the plan is changed.
