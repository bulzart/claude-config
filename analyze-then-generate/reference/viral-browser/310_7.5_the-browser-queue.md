### 7.5 The browser queue

Dynamic pages (trend charts, marketplace pages, ad libraries, shop pages) often cannot be read by `WebFetch`. Each agent lists what it could not read in **its own file per candidate**, `30-research/queue-<C>.md` (several agents write at once, so one shared file would lose lines), one line each: `- <lane> | <URL> | <what to read>`. **Only when the user chose "web plus my Chrome"**, the main session loads the browser tools (`ToolSearch`), calls `tabs_context_mcp` first, opens a new tab per page, reads it (`get_page_text` or `read_page`; filters and a region selector may be set; nothing is submitted, no login, no purchase, no dialog-triggering control), registers the evidence rows (`--independent yes`), and stops at `browser_pages_per_candidate[depth]` pages per candidate (EU and global evidence depends on these pages, since `WebSearch` is US-only). Pages beyond the cap, or with Chrome off, stay "unreachable" in the dossier and cap that lane's confidence.

**The browser pass sets the price.** The marketplace pages are where the price a product really sells at, and the sold counts that go with it, can be read; after the pass the main session re-runs `T econ --cand` **for every candidate whose market price differs from the stored one** (not only the ones that now look like passes: a leg left at an old stored price goes unnoticed until the red team reads it at the market price) at the retail price those pages support (the stored result of that market is replaced, the superseded calculation row is withdrawn with `T evidence retract` and the reason). (The miss behind this rule: a retail price taken from search summaries of a cheaper variant understates what units of the exact specification really sell for, and the same inputs at the market's price can change the verdict.) **How to read a page cheaply:** a search result page is read with a short read-only script that returns each result's title, price, rating count and sold badge (a few hundred tokens), a trend chart is read from a screenshot (the values are estimated from the curve and noted as such), an official rules page is read as text; a tariff-schedule site is not worth a page (its text is very long and omits the special-duty lists). A page that informs several candidates counts for each of them. Search results sorted by sponsorship carry paid positions; the sold badge is the platform's own count, rounded down. If the browser extension disconnects (after two attempts), stop and report it: the pages not read stay "unreachable" and the lane's confidence says so. The tab group can vanish between calls: call `tabs_context_mcp` with `createIfEmpty` again before each batch. **Price and cost are read at the same variant:** a price read for one variant (material, size, pack count) is paired with the supplier price, carton size and weight of that same variant, never with the cost of a cheaper proxy the research agent used; after the pass, re-read the supplier price of the variant the price was read at (a supplier listing page that `WebFetch` can read is enough) and re-run `T econ` with both. A price from one variant paired with a cost from another makes a candidate pass on a pair that does not exist.
