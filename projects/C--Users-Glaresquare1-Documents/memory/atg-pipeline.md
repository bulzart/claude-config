On 2026-10-11 the user asked for a new pipeline `/analyze-then-generate` with a new Analyze sub-mode `viral-browser` (next to Recreate and Create) and a build prompt file like `analyze-then-pick.txt`. They named `analyze-stack-build-prompt.txt` as the base, but that file is the old `/analyze-stack` spec (Modes 1-3); the Recreate/Create structure they described is `analyze-then-pick.txt`, so the fork was made from the ATP library (snapshot 2026-10-10 14:04) and from that build prompt. `/analyze-then-pick` itself was not changed.

**What exists**
- Command `~/.claude/commands/analyze-then-generate.md` (contract items 23-25, steps V1-V9 after A10), library `~/.claude/analyze-then-generate/` (own toolkit `scripts/atg.py`, the ledger copied with CE-001..CE-029, a fresh `learning-log.md`, all references and model guides), the playbook `reference/viral-browser.md`, config `viral_browser` in `config.json`, build prompt `Documents/prompts/analyze-then-generate.txt` (generated from `analyze-then-pick.txt` plus a Viral-Browser block; same CRLF prose style).
- Viral-Browser: asks market (US/EU/global) and price range (plus selling model, Chrome yes/no; exclusions and how they sell come from the user's message only); per-reference viral cards (product layer apart from mechanism layer, a one-line `Facts:` JSON whose `category` is a niche label the agents reconcile into a run-level niche vocabulary, `T niches`; **no niche, product or category name is allowed in any script or config, user rule 2026-10-11: names are collected data, decided by AI agents**); `viral-stats` corpus profile and niche concentration; mechanism map, essence, fit profile; 12-20 specific candidates from five sources (the references' own products are one); `candidates shortlist` enforces the pool balance, the shared-word check and a current niche audit before research (a fresh niche-audit agent; `niches merge | distinct | audit`; candidate statuses and the contribution are set only by toolkit commands); up to 3 research agents (WebSearch/WebFetch, origin-blind dossiers, evidence rows graded A-D with a signal and an independence flag; economics needs a grade A/B sourced-input row besides the calculated grade C row, run per market with the lowest contribution counting), a fresh blind scoring agent (the main session never scores), a red team on the gated final targets, rubric scoring with floors, six gates, independent-evidence cap, niche cap 2, ties broken by independent rows, contribution, then name; `rank --apply` refuses without red-team verdicts, defence notes (30+ chars), statistics newer than the last vocabulary change (rerun `viral-stats`) or a `--reason` for `--force`; one backfill wave; three picks + blueprints in `RUN/deliverables/`; optional continue-to-Create on the user's yes (enters the Create flow at its start for the new inputs). Nothing is generated (no model, no credits, no CapCut). Two independent reviews' findings were folded in the same day (see `learning-log.md`).
- **Create is a blend here (user, 2026-10-11):** Create must not be hardened into re-making the reference samples. It understands the references (craft sheet, audience, trend) AND the product (supplied assets → `30-assets/product-insights.md`, the "product insight sheet") and blends both to design the most engaging video; families are evidence and ingredients, never a menu; hybrid style groups are allowed; every seed names its blend and passes the blend test and the template-lock test (`creative-direction.md` §5.0b). Create's structure, length, payoff timing and pacing QC follow the mechanisms the blend borrows, never one family's profile (Recreate keeps the source's family profile); the product insight sheet holds up to six truths from the supplied assets only. Not ported to `/analyze-then-pick`.
- Toolkit additions: `viral-stats`, `candidates` (add/list/set/pool/shortlist/score/rank/show), `evidence`, `econ`, `new-run --submode`, `inventory --as baseline`, `prep-all --set baseline`.
- Ledger modes/causes for picks: `--mode analyze-viral-browser`, causes research / scoring / bias / evidence.

**Why:** the user is building an owned-inventory store (see [[user-kosovo-ecommerce-founder]]) and wants the next products to sell found from what made viral videos spread, without the references' dominant niche (e.g. pet tools) deciding the answer.
