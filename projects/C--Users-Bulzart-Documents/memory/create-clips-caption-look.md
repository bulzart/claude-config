This SUPERSEDES the free font family.

**Why (root cause, found by reading the Loupe code and the video-04 timeline):** the box numbers were tuned with the user on Luckiest Guy. CapCut boxes the WHOLE LINE of a text (ascent + descent), so the font's metrics decide the box's size and place. Luckiest Guy: line 1.0 em, ascent 704 / descent 297, capitals as tall as lowercase. Barlow Black: line 1.2 em, x-height 0.52 em, baseline lower in the line, so the same numbers gave a box 2x the word's height, off it (our demo). Our as-is lowercase text and thin outline made it worse.

**The box look (video 04's `captions` + `word_box` in `40-briefs/video-04-timeline.json`):** font `LuckiestGuy-Regular.ttf` (Loupe fonts folder), upper case, fill #FFFFFF, black outline 0.18, shadow on, box radius 0.3 / alpha 1 / style 0 / pad 0.08 (0.06 since 2026-11-20) / v_offset 0.15 / gap 0.55 em (our old default gap 0.7 was an earlier Loupe value), 3 words a caption, entrance mini-zoom 0.12 s (ours: fade-in in shorts only), Loupe size 5.5 on 16:9 / 10 on 9:16 (em about 5.6%).
**How to apply:**
- Never put a font in an EDL; the one exception is a character the look's font cannot draw (Luckiest Guy: no Slavic/Turkish letters, Cyrillic, Greek; Montserrat Bold: no Cyrillic, Greek: `cc.py captions` lists `font_missing_glyphs`, says `house_font` = the look's own font; `capcut-build` makes it a problem). The user's per-run font option `captions_font` was removed; `captions_color` (box colour, box look only) stays, and the agent matches the colour to the video.
- Our size stays `auto` = em 4.6% of the smaller side (CapCut 4.5 on 1080p, 8.0 on 9:16 in Luckiest Guy; 5.5 / 9.8 in Montserrat Bold), about 20% smaller than Loupe's own 5.5/10: a number to change if the user wants Loupe's size. The 4.6 is my own judgement of "small/normal for phones" (inside my 4.0 to 5.0 guide), not a measured or looked-up standard.
