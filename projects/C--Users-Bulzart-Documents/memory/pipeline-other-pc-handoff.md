User 2026-11-15: "verify that if i clone it in another pc the guide works and the command executes correctly". The guide the other agent wrote (`C:\Users\Bulzart\Documents\create-clips-create-static-setup-guide.md`) had never been run on a clean machine; running it found these, now fixed in the guide and the repo:
- **Hard-coded paths.** `commands/create-clips.md`, `commands/create-static.md` (their `CC`/`CS`/`PY` banner and allow-list), 15 `cc-*`/`cs-*` skills and three configs (`create-clips`, `create-static`, `analyze-with-loupe`) name `C:/Users/Bulzart/...`. `create-clips/scripts/setup_pc.py` (plain, stdlib only, `--check`, `--dry-run`, idempotent, no-op on this PC, one regex pass with a name boundary so `BulzartX` is not mangled) rewrites exactly those and prints a checklist. `tests/test_setup_pc.py` guards it (made-up original PC via `SETUP_PC_OLD_HOME`). Never reintroduce a hard-coded path anywhere else the commands read.
- **`git clone` of this repo fails on Windows** ("Filename too long" under `analyze-stack/research/miko/...`) and leaves a half checkout without `commands/` and `create-clips/`: the guide's clone line needs `-c core.longpaths=true`.
- **Whisper is NOT downloaded automatically** (`whisper.local_files_only` true): a new PC fails with `LocalEntryNotFoundError ... cannot find an appropriate cached snapshot folder` until `python -c "from faster_whisper.utils import download_model; download_model('medium')"` (1.4 GB) is run.
- **create-clips depends on `analyze-with-loupe/`** (`awl_home`): caption fonts, `data/capcut-catalogue.json`, `scripts/awl.py`, and the shared CapCut store lock (`<awl_home>/runs/.capcut-store.lock`, also create-static's `capcut.store_lock`). The old guide said `awl_home` could be "any folder": wrong. The copy list must include `analyze-with-loupe\`.
- `requirements.txt` of both tools existed only in a local commit (f886eff), not on `origin/pc`; pinned versions are not used (`av<19` only): a clean venv resolved today to faster-whisper 1.2.1, ctranslate2 4.9.0 (this PC 4.8.5), Pillow 13.0.0, numpy 2.5.4, cv2 5.0.0, librosa 1.0.1 and passed `test_proc` 65/65.
- `install-background.ps1` had the owner's folders hard-coded (now derives them from its own location; the extension id is pinned in the manifest `key`, so a default id works). Needs `CC_SOURCE_KEY` in Chrome's environment (fully restart Chrome after setx).
- The SessionStart resume hook (`hooks/atp_resume_note.py`) is not part of what a friend copies: `test_resume_hook` / `t03_resume_hook` fail in a copy, by design. `capcut-cli` must be exactly 0.25.0 (`npm install -g capcut-cli@0.25.0`; latest on npm is 0.34.0). With no sound-effects folder `sfx-scan` fails plainly (exit 2) and the videos get no sound effects.
- The repo is the owner's whole `.claude` (memory notes, settings, hooks): the guide has the friend copy only the needed folders instead of cloning over their `.claude`.
- **`test_edit`'s "four capcut-compose calls at once" failed in about one run in three** in a copy (0 of 5 in the original folder, while the PC was idle): the real error, captured by an instrumented copy, is `PermissionError [WinError 5]` on the atomic replace of `60-outputs/S01/compose-spec.json`: the four calls build the SAME video, so they write the same file at the same instant (a Windows replace race of the test's setup, not of the CapCut index lock; real builds are different videos in different folders). The test now re-runs a call that died exactly that way. A retry on `PermissionError` inside `cc_common.write_text` would remove the race for good, but that module is locked: ask before unlocking.

**How it was verified (no second PC exists):** `subst Z:` onto a scratch folder so the "other PC" has no trace of the owner's name, a clean venv (`python -m venv`, both requirements files, 110 s), the guide's own PowerShell blocks parsed out of the markdown and run as files, the friend's `.claude` built from `git ls-files -co --exclude-standard` (what a clone holds after the auto-commit), profile variables (`USERPROFILE`, `LOCALAPPDATA`, `APPDATA`) pointed at the fake home, both full test suites run from that copy. Not done: a real second machine, a real GitHub clone by someone else (the remote's `pc` branch must be pushed first, the user's call), CapCut itself opening a project, the real Chrome starting the host with the key.
