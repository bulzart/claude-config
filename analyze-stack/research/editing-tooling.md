## 2. Recommended architecture

```
90-postgen\
  edit-plan.json        <- single editable source of truth (written by the editing agent; owner may hand-edit)
  transcript.json       <- faster-whisper word timestamps (or VO transcript), same shape HyperFrames uses
  captions.ass          <- generated from transcript.json + edit-plan.captions (TikTok style)
  project\
    capcut\<draft-name>\        <- CapCut draft folder (copied into CapCut's Projects dir by install step "register")
    otio\final.otio             <- + final.fcpxml, final.xml (FCP7), final.edl
    descript\project.json       <- project_id, composition_id, share/download URLs (only if the MCP path was used)
  render\final.mp4      <- ffmpeg render of edit-plan.json
  final-check.md
```

Data flow (fixed, engine-independent):

1. `clip-qa` + `trend-brief` decide the edit → agent writes **`edit-plan.json`**.
2. `python tools\edit\make_captions.py --plan edit-plan.json` → `transcript.json` (faster-whisper, `word_timestamps=True`) → `captions.ass`.
3. Builders, all reading the same plan:
   - `python tools\edit\build_capcut_draft.py --plan edit-plan.json --template research\capcut-draft-sample --out 90-postgen\project\capcut\` (+ `--register` to copy into CapCut's Projects folder and append to `root_meta_info.json`; only when CapCut is closed).
   - `python tools\edit\build_otio.py --plan edit-plan.json --out 90-postgen\project\otio\` (`.otio` + `fcp_xml` + `fcpx_xml` + `cmx_3600`).
   - `python tools\edit\render.py --plan edit-plan.json --out 90-postgen\render\final.mp4` (ffmpeg).
   - Optional: `descript_push.md` instructions → main session calls `import_media` (direct upload) + `prompt_project_agent` + `export_timeline`.
4. `final-check.md` = ffprobe of `final.mp4` (1080x1920, 30 fps, High, yuv420p, AAC 48 kHz, faststart) + loudness (`loudnorm` pass-1 JSON) + caption timing sanity.

## 3. The re-edit loop (owner edits → we re-render)

| Path | Owner edits in | How the edit comes back | What we re-render |
|---|---|---|---|
| CapCut | CapCut 9.4 (open the registered draft) | (a) Owner exports MP4 from CapCut = final; or (b) we re-read the re-saved `draft_content.json` (plaintext in 9.4; CapCut rewrites it and keeps `draft_content.json.bak`) with `tools\edit\capcut_to_plan.py` to update `edit-plan.json` (cuts/timing/speed/transform round-trip; text/effects only if the shapes are known) | `render.py` |
| OTIO | Resolve / Kdenlive / Premiere / FCP | Owner exports `.otio` (Resolve 18.5+, Kdenlive 25.04+, Premiere 25.6+) or FCP7 XML → `otio.adapters.read_from_file` → `otio_to_plan.py` | `render.py` |
| Descript | Descript web app / Agent Underlord | `export_timeline` (format `davinci_resolve` or `premiere` or `fcp`) → same OTIO importer; or `publish_project` download_url = final | `render.py` or take Descript's MP4 |
| ffmpeg | `edit-plan.json` by hand (or agent) | it *is* the source | `render.py` |

Round-trip caveats (DOC): OTIO carries clips/tracks/timing/markers/dissolves; no captions (OTIO "has no title schema" — capcut-cli docs), no effects. CapCut → FCP7 XML converter exists (`Ersiter/Jianying-CapCut2XML`: multi-track video/audio, trims, transforms, average speed survive; text/stickers/effects/transitions/keyframes do not).

### A.2 How a new draft becomes visible in CapCut (registration recipe)

DOC (capcut-cli schema overview): "CapCut scans the platform-specific projects folder on launch, reading `root_meta_info.json` and directory metadata … You must restart CapCut to refresh the project list after folder changes." pyCapCut README: "you may need to enter and leave an existing draft, or restart CapCut, to refresh the draft list." pyCapCut never touches `root_meta_info.json`; it creates the folder + `draft_meta_info.json` + `draft_content.json` only.

Recipe for `build_capcut_draft.py --register` (do it with CapCut **closed**; back up `root_meta_info.json` first):

1. Copy the template folder tree (use the live `0915` layout, i.e. everything listed in A.1 minus `*.bak`, `template*.tmp`, `draft_cover.jpg`) to `<root>\<draft_name>\`.
2. New uuids: `draft_id` (meta + root index), timeline `id` (draft_content.id, `Timelines\project.json` main_timeline_id + timelines[0].id, folder name, `timeline_layout.json`), every track/segment/material id. Rewrite `common_attachment\attachment_id_mapping.json` (root and mirror) with `{"short_id":"1000"+i, "uuid":<segment id>}` and `next_index`.
3. Write `draft_content.json` at root **and** `Timelines\<timeline id>\draft_content.json` (identical bytes, `ensure_ascii=False`, no trailing newline needed).
4. Write `draft_meta_info.json` with one `draft_materials[type 0]` entry per media file (ids = `local_material_id`s) and `draft_virtual_store.json` type-1 children for the same ids.
5. Append an entry to `root_meta_info.json.all_draft_store` (copy the sample entry, replace paths/ids/times; `tm_*` in epoch µs) and set `draft_ids = len(all_draft_store)` (UNCERTAIN: the field could be a counter rather than a count; the sample has 1 draft and `draft_ids:1`).
6. 7. Keep our own copy in `90-postgen\project\capcut\` so a CapCut re-save never destroys the generated original.

Risks: CapCut auto-updates; capcut-cli reports **10.x rejects tool-written drafts as corrupted** → turn off CapCut auto-update / keep 9.4.0.4015 until a 10.x draft sample is captured.
