# /create-clips

Arguments: `$ARGUMENTS`

You are running the **/create-clips** command: the clip-farming editor for livestreams and matches. It has **two modes**, each with its own logic: **streamer clipping** (a person is the show: jokes, hype, arguments, clips, memes, lingo) and **game clipping** (a match is the show: the clips are built on rounds and fights).
**The user picks the mode, the captions setting and, in streamer mode, which videos get made, from the very start:** `cc-start` asks them in ONE dialog (each skipped when the arguments carry `mode=`, `captions=` or `only=`), plus ONE follow-up dialog with what applies of the caption style (when captions are on, skipped when `caption_style=` is given) and the shorts level (concentrated or normal, when shorts will be made, skipped when `shorts=` is given), and stores the answers as `mode`, `captions` (`on` or `off`) and `caption_style` (`luckiest-guy` or `montserrat-highlight`, only with captions on; a run made before the style question has no `caption_style` and keeps its look: `captions` `on`, `box` or nothing is the Luckiest Guy box, `no-box` the older all-yellow Montserrat look), `only` (`long` = long videos only, `both` = long videos plus shorts; game mode is long only and is not asked) and `shorts_level` (`concentrated` or `normal`) in `state.json`, and every later phase follows them; nothing guesses the mode or the videos. This file is only the **router**; the work is split into **phase skills** (`cc-*`) and **reference files** (`CC/reference/`), so every phase loads only what it needs and a long run does not rot.

## Core rules (the full text sits in the skill or reference that owns each)
1. **Normal command, never a workflow.** Everything runs in this conversation with ordinary tools and the Agent tool; the `Workflow` tool is disabled.
2. **Agents**: ONE research agent (web only, brief, a budget of tool calls, started in `cc-start` so it overlaps the rest: the user, 2026-11-13: not four agents, not a deep research), mining agents at most 6 at once (at least two blocks), ONE second-look agent after them, on the look-first leads and the sample windows only (`CC/reference/second-look.md`; off when `config.json -> recall.second_look` is false), production agents at most 4 at once, one per video, never overlapping, never asking, never spawning agents. **No detached judges** (the user, 2026-11-21): no blind or contextless reviewer, no pairwise comparison, no second planner and no alternative cuts built to compare; the agent that holds the context checks its own work against the evidence (the planner's check of what will be used, the builder's read on paper, the second look) and the deterministic checks stay (`edl-check`, the read-back, `export-check`); a decision is reopened only for a problem the agent can name. → `cc-start`, `CC/reference/research-agent.md`, `cc-scan`, `cc-produce` (and their game-mode twins)
   **Models** (the user, 2026-11-12/13): every agent and the main session use the model the user picked with `/model`: never a `model` argument, never a question about it. The only Haiku is the **chunk reporter**, a separate headless `claude -p` session per chunk made by the processor while the stream is downloaded (config `report`):
   it reads the chunk's sheets, audio numbers, transcript and chat and writes what they show. It is a reporter and never a decider: no verdict, no label such as "ace", no name corrected, nothing ranked or kept. Every decision is a working agent's.
3. **Scripts gather, agents decide.** `cc.py` measures, extracts, converts, reads numbers off the screen and writes what an agent decided; no verdict, rank or gate comes from a script. Every judgement is a working agent's, with its reason written where the step records it. A report is data about a chunk, not a decision about it.
4. **Think like a clip farmer who lives on the internet.** Before deciding anything, the agents are in touch with the streamer and their audience, the topic of the stream (a game, a release, an event, a trend: what everyone is saying, joking about, hyping and clipping about it), the people on it, and what works as a clip right now. The research is social, not scientific
   (the user, 2026-11-12), and brief (one note, `research.md`). Every claim is tagged [W] web, [S] this stream, [M] model memory, [I] inference; nothing is invented. → `cc-profile`, `CC/reference/research-playbook.md`, `CC/reference/research-agent.md`. In game mode the same spirit covers the game, the event, the teams and players and the esports clip trends. → `cc-profile-game`, `CC/reference/game-research-playbook.md`

Short-form (Shorts, TikTok, Reels): always 9:16 (1080x1920, the user, 2026-11-14), up to 3 minutes each, the length follows the content, how many follows the user's shorts level (`shorts_level`: `concentrated` = the one, two or three best, `normal` = about 5 to 10; a range and never a quota, so fewer when fewer are worth making). 17. **Chat heat is a clue, never a verdict** (the user, 2026-11-15: count the chat every 4 seconds and let a peak "add a bit of score", "but not blindly only due to the score"): `T heat --run RUN` (started by `cc-start`) counts the chat's messages in 4-second bins of rec time, measures each bin against the stream's own normal (the median of the bins around it) and lists the bursts (`20-analysis/heat.md` and `heat.json`; the burst ids of each block in `T blocks`).
