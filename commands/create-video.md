# /create-video — STATIC ONLY · YOUTUBE LONG-FORM

Input: `$ARGUMENTS`. This is a **normal Claude Code command**, not a Claude workflow, automation, or multiple-mode selector. It has exactly one production pipeline: reference research → choose a niche → invent and research an original long-form story → fully narrated image-led video → CapCut project/export. Never ask which mode to run. Never load or invoke legacy phases, generic video-editing flows, browser inspection services, or video-to-video generation services. No external monitoring app is used.

**Paths.** `STUDIO = ~/.claude/static-studio/`; the executable is `python "$HOME/.claude/static-studio/scripts/static_core.py"` (on Windows, use the Python 3 installation already configured in Claude Code; `$HOME` is the Git Bash home directory). `RUN` is the absolute run folder returned by `init`, `clone`, or supplied on `resume`. The command is stored in `~/.claude/commands/create-video.md`. Keep all artifacts under `RUN`. Never modify the user's `references/` sources.

## Entry / resume

1. If `$ARGUMENTS` starts with `resume`, read `RUN/state.json` and `RUN/todo.md`; call `static_core.py status --run "RUN"`. Verify real files rather than trusting conversation memory. Continue the earliest incomplete stage; **never re-ask a choice already present in the run**. This works across `/compact` or a new chat.
2. If it starts with `more`, use the existing `RUN` and its locked niche/look/narrator. Ask only for a count when absent, then use new video IDs, new original topics and new duration locks. First `scan` for newly added references and study only new ones. Never create a new run for more videos.
3. If it starts with `clone`, run `static_core.py clone --from-run "RUN"`; keep evidence/cards, start an independent new niche and new production. The old run remains untouched.
4. Otherwise, the **first requirement is a path to `references/`**. If `$ARGUMENTS` contains a path, use it; if not, ask exactly for that folder path. `static_core.py doctor`, then `static_core.py init --references "PATH" --slug "youtube"`, then `scan`. The returned run path is authoritative. `prepare --run "RUN" --dry-run`, then `prepare --run "RUN"` with local Whisper enabled. If files are corrupt/missing, report and skip those files explicitly; never silently treat missing speech as silence.

## Core execution contract

**A. Watch, listen, classify, understand.** Analyze each unique video as a cohesive whole: original audio/Whisper word-timestamps, 5 fps sampled visual coverage, high-fps windows for ambiguous transitions, transcript, story architecture, scene progression, emotional movement, narrator character, pacing, music, retention hypotheses, title/thumbnail promise. Run `av-profile --run "RUN" --refs ...` and read each reference's **watch sheets** (one image per minute: frames every 5 s with the words spoken under them) beside its measurements (pace and its swings, how the voice moves, the bed under it, cuts, holds, motion): it is how an agent watches a film. Reason about what makes each one *enjoyable*, not only what it contains (10 §1). Create `20-analysis/cards/V###.json` and `20-analysis/V###-notes.md`. Cross-classify by **niche**, **story form**, **runtime family**, **language** and **visual medium**. Explicitly distinguish verified observation, plausible explanation and unknown metrics. Write niche-specific syntheses and derive a `20-analysis/creative-profiles/[cluster-slug].md` per cluster (editorial implications for making a new video in that direction; see §02); never average unrelated formats. Run `cohorts --run "RUN"`. When a card is weak, inspect the actual reference again.

**B. Ask one intentional choice: niche.** Present the discovered niches and one short indication of what *makes each engaging*. The user picks a niche (or explicitly delegates that choice). From then on, **you invent the subject, premise, angle, chapters, and execution autonomously**. Do not ask users to choose one of your titles or scripts by default. Prompt only when their actual choice is necessary: custom vs comparable-reference Standard length, count (default one), language, narrator, generation engine and a material cost authorization. Persist those choices; no repeating.

**C. Lock long-form duration BEFORE script, speech, images or CapCut.** Standard means median of **at least two user-visible, same-niche, same-story-form, comparable, long-form reference IDs**; use `length --mode standard --refs ...` after showing IDs/durations. A Short cannot set the length for a history narration. For custom length use `--mode own --minutes ...`. Defaults: YouTube **16:9, 1920×1080, 30 fps**, with a user-adjustable long-form minimum; no vertical templates. The lock is immutable without an explicitly authorized length revision; don't silently shrink it to match generated audio or sparse visuals.

**D. Make a genuine new story, not a reference remix.** Read stages 02–03. Explore at least five *different editorial approaches* (they differ in perspective, scale, structure, voice or visualization, not only in subject; five battles told the same way are one approach); select on substance, credible evidence, distinctive viewpoint, human relevance, an earned ending and compatibility with runtime. Study source documents for factual topics independent of reference videos, create claim/source ledger; separate fictional hypothesis from fact.

**Creative direction comes first** (read 10; it is the director's manual). In `40-plans/video-NN/direction.json`: the measured reference evidence, the five approaches and the chosen one with its runner-up, the episode strategy, and **two or three audiovisual treatments** (narrator, writing voice, pacing, visual language, sound, how picture and voice relate) each written out in three sample moments. Then one blind read of the treatments (`review-packet --kind treatment`, one fresh agent, `review-record`, every finding answered), your decision with reasons, and `direction-lock`, **before any script exists**. Nothing here is a niche formula: two videos in one niche may need opposite treatments.

Then, from the locked treatment: `blueprint.json`, `beat-map.json` (each beat with its `experience`, `narration_direction`, `visual_intent`, `sound_direction` and `pace`), `script.json`, `editorial-review.md` (your own self-audit, with `writing_signals`), plus human-readable outline and title/thumbnail options. Each beat must move the story forward and be mapped to narration lines and a planned visual purpose. Do not pad or speed-read. **How the narration sounds and breathes is decided here, not at the audio stage.** It flows from the treatment and each beat's direction, read against the references' measured delivery.
- Inline audio tags come from the whole catalogue (`STUDIO/data/elevenlabs-audio-tags.json`, read through 05). The agents choose what fits, or nothing.
- Each long pause is realised by a tag or an edit hold (`pause_via`, 03).
- Each tag, pause and `content_flags` hit gets its line in `editorial-review.md`.

Then the **cold read**: `review-packet --kind script`, ONE fresh agent whose whole prompt is to read only that packet and follow it, `review-record`, and an answer to every finding (revised with its lines, kept if minor with why, disputed with why). A major finding means revising and a fresh round-2 read by a new agent; after round 2 you decide, on record. Never write or soften a reviewer's findings. Run `plan-check --run "RUN" --video NN`; **do not buy TTS or pictures if it fails**. Fix the *story*, not just the numbers.

**E. Narration and production.** Read stages 04–05. Select the narrator the locked treatment describes (`voice-candidates`: five candidates described by character, register, age and accent; each preview's delivery is measured, because no agent here can listen; a preview's pace does not predict the real pace; the user may listen and overrule) and keep the voice consistent inside a run (the spoken language may be chosen per video). `voice-pick` locks it. Only `eleven_v4` / `eleven_v4_turbo` are used. ElevenLabs generations are paid, so the order is:
1. `tts ...` without `--execute`: the character, part and credit forecast.
2. `tts ... --max-parts 1 --execute`: the first real part *is* the calibration, paid once and kept. The tool refuses more parts until the voice is measured.
3. `narration-measure`: the real pace, line gap, tag costs, and pauses next to the references', measured exactly as the references were; and `delivery.json`, how the voice moves beat by beat next to what each beat asked for. A beat meant to lift that measures flat is rewritten in the parts not yet recorded.
4. `plan-check`: `real_forecast_s` inside the export window. If not, change the words of the parts not yet recorded, or the holds. Never force pace with a delivery tag or by editing delivered audio.
5. The rest of the parts.

Continue only after the account, voice, model and charges are accepted. An edited line later re-records only the part that holds it (`--rerecord-changed`). **Partial, exhausted, missing or short narration is a BLOCKER.** `audio-check` must pass before stills and edit; it includes narration plus planned holds inside the export window. Preserve partial chunks for resuming; never cut chapters to make a failed recording look done. Create an image style bible from the locked treatment's visual language and a shot plan from each beat's `visual_intent`, every shot saying what NEW thing its picture gives (`new_thing`); `shot-check` before any still is generated (it also lists near-identical prompts and long runs of one composition); generate stills with available OpenAI Images or the optional local image worker, or prepare prompts for user-supplied stills. Add charts, maps, time lines, restrained illustration animation and on-screen text **when they improve comprehension**; do not turn every shot into a wallpaper slide or a frenetic montage. Optional instrumental music and sound design support the scene rather than bury it.

**F. CapCut and actual export.** First `narration-measure` on the complete narration, then `retime-shots --render-narration`: every shot is timed to the real narration and its edit holds (`edit-plan.json`, `narration-edit.wav`). The project uses those times, never the plan's estimates. Use connected CapCut MCP/CLI as available to create a *real editable project*, no unsupported invented operations. Create `70-edit/video-NN/timeline.json` from the actual project (shot ranges, beats and narrative purpose), then `timeline-check --run "RUN" --video NN`; listen at joins and watch the whole opening, chapter transitions and ending. A CapCut draft is **not** an exported file. After an accessible MP4 is exported, run `export-check --run "RUN" --video NN --file "actual.mp4" --deep`, then the **final watch review** of that exact file: `av-profile --video NN --file` (its watch sheets), `review-packet --kind final --file` for ONE fresh agent who judges it against what each beat was meant to feel like, `review-record`, every finding answered; fix and re-export as needed (a new file gets its own read). `release-check` confirms every gate for that file. If export is not available, report that as unverified; never claim to have watched a file not seen. No agent here can play video or hear audio: the sheets, transcripts and measurements are what is read, and the user is offered an optional watch.

**G. Critical pass before delivery.** Read stage 06. Evaluate title/thumbnail promise, originality, human interest, factual honesty, macro/micro pacing, viewer's mental participation, audio quality, shot-purpose/continuity, rhythm/breathing room, final satisfaction. Fix unearned hooks, repetitive middle, weak ending, historical anachronisms, bad compositions, robotic narration, frame/caption clutter and incomplete runtime. The goal is exceptional work, not a fictitious guaranteed “10/10” score. Use up to two research agents and up to three production agents when useful, with non-overlapping responsibilities, plus the three fresh readers (treatments, script, final cut: one agent each, holding only its packet); do not spawn a judge bureaucracy. A passed gate means the process happened, never that the video is good: say so in the report. Verify artifacts; communicate blockers plainly.

## Non-negotiables

- One purpose only: **new long-form YouTube videos built from narrated still images/graphics**. No other generation or editing modes, no unrelated prompts/assets, no reuse of source-video images or speech as final footage.
- Ref clips are **evidence about craft**, not license to reproduce another creator's words, distinctive footage, visual identity or unsupported factual claims. Preserve provenance; independent research for facts.
- Source and final frame timing matter. 5 fps is a broad coverage rate, **not literally every native frame**. For exact transitions, extract a full-frame window or use `prepare --full-fps --ids V###`; record the difference rather than falsely claiming every frame was viewed.
- The author is responsible for decisions. Machine checks measure objective properties, not taste or truth. No hard formula for hooks, number of chapters, humor frequency, zoom every few seconds or cliffhangers.
- Keep a progressing `RUN/todo.md`; use files as durable handoffs. Resume from what exists. Never run a Claude workflow. Never spend credits on a failed preflight. Final product is an actual CapCut project and, when exported, a verified video.
