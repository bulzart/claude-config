# /create-video — STATIC ONLY · YOUTUBE LONG-FORM

Input: `$ARGUMENTS`. This is a **normal Claude Code command**, not a Claude workflow, automation, or multiple-mode selector. It has exactly one production pipeline: reference research → choose a niche → invent and research an original long-form story → fully narrated image-led video → CapCut project/export. Never ask which mode to run. Never load or invoke legacy phases, generic video-editing flows, browser inspection services, or video-to-video generation services. No external monitoring app is used.

**Paths.** `STUDIO = ~/.claude/static-studio/`; the executable is `python "$HOME/.claude/static-studio/scripts/static_core.py"` (on Windows, use the Python 3 installation already configured in Claude Code; `$HOME` is the Git Bash home directory). `RUN` is the absolute run folder returned by `init`, `clone`, or supplied on `resume`. The command is stored in `~/.claude/commands/create-video.md`. Keep all artifacts under `RUN`. Never modify the user's `references/` sources.

## Entry / resume

1. If `$ARGUMENTS` starts with `resume`, read `RUN/state.json` and `RUN/todo.md`; call `static_core.py status --run "RUN"`. Verify real files rather than trusting conversation memory. Continue the earliest incomplete stage; **never re-ask a choice already present in the run**. This works across `/compact` or a new chat.
2. If it starts with `more`, use the existing `RUN` and its locked niche. Each new video gets its own creative direction and narrator choice; keeping the run's look and voice for a series identity is a choice made and recorded there (`voice-pick` with a reason), not an automatic carry-over. Ask only for a count when absent, then use new video IDs, new original topics and new duration locks. First `scan` for newly added references and study only new ones. Never create a new run for more videos.
3. If it starts with `clone`, run `static_core.py clone --from-run "RUN"`; keep evidence/cards, start an independent new niche and new production. The old run remains untouched.
4. Otherwise, the **first requirement is a path to `references/`**. If `$ARGUMENTS` contains a path, use it; if not, ask exactly for that folder path. `static_core.py doctor`, then `static_core.py init --references "PATH" --slug "youtube"`, then `scan`. The returned run path is authoritative. `prepare --run "RUN" --dry-run`, then `prepare --run "RUN"` with local Whisper enabled: Whisper medium on the GPU, always (`doctor --whisper` proves it loads and runs there). A GPU failure stops with its cause; it never falls back to the CPU, which runs only on the user's explicit yes (`--device cpu --cpu-approved "<their words>"`). If files are corrupt/missing, report and skip those files explicitly; never silently treat missing speech as silence.

## Core execution contract

**A. Watch, listen, classify, understand.** Analyze each unique video as a cohesive whole: original audio/Whisper word-timestamps, 2 fps sampled visual coverage (a frame every half second, each at its own timestamp on the transcript's clock; a run keeps the rate it was analysed at), closer looks at a higher rate for brief or ambiguous stretches (`inspect-window`), transcript, story architecture, scene progression, emotional movement, narrator character, pacing, music, retention hypotheses, title/thumbnail promise. Run `av-profile --run "RUN" --refs ...` and read each reference's **watch sheets** (one image per minute: frames every 5 s with the words spoken under them) beside its measurements (pace and its swings, how the voice moves, the bed under it, cuts, holds, motion): it is how an agent watches a film. Reason about what makes each one *enjoyable*, not only what it contains (10 §1). Create `20-analysis/cards/V###.json` and `20-analysis/V###-notes.md`, and the reference's **content review** (01, `content-review --ref V### --shot-sheets`, then `--file`: every shot seen once, every decision proportionate and grounded in its frames, words and times): its graphic or harmful segments and, kept apart from those, its religious, superstitious or holiday material, each with its timestamps, role in the story, what depends on it and what is done with it. A segment is excluded selectively; the rest of the reference stays useful. Cross-classify by **niche**, **story form**, **runtime family**, **language** and **visual medium**. Explicitly distinguish verified observation, plausible explanation and unknown metrics. Write niche-specific syntheses and derive a `20-analysis/creative-profiles/[cluster-slug].md` per cluster (editorial implications for making a new video in that direction; see §02); never average unrelated formats. Run `cohorts --run "RUN"`. When a card is weak, inspect the actual reference again.

**B. Ask one intentional choice: niche.** Present the discovered niches and one short indication of what *makes each engaging*. The user picks a niche (or explicitly delegates that choice). From then on, **you invent the subject, premise, angle, chapters, and execution autonomously**. Do not ask users to choose one of your titles or scripts by default. Prompt only when their actual choice is necessary: custom vs comparable-reference Standard length, count (default one), language, narrator, generation engine, a material cost authorization, and the **captions**, asked once in the same start dialog with no default: **Luckiest Guy — Word Box** (white capitals, the spoken word on a rounded colour box), **Montserrat Bold — White Text / Yellow Active Word** (the spoken word yellow, the rest white, black outline, no box) or **No Captions**; record it with `captions-choice --run "RUN" --captions on --style luckiest-guy|montserrat-highlight` (or `--captions off`). Persist those choices; no repeating. A run made before this question existed is asked once, when its edit begins.

**C. Lock long-form duration BEFORE script, speech, images or CapCut.** Standard means median of **at least two user-visible, same-niche, same-story-form, comparable, long-form reference IDs**; use `length --mode standard --refs ...` after showing IDs/durations. A Short cannot set the length for a history narration. For custom length use `--mode own --minutes ...`. Defaults: YouTube **16:9, 1920×1080, 30 fps**, with a user-adjustable long-form minimum; no vertical templates. The lock is immutable without an explicitly authorized length revision; don't silently shrink it to match generated audio or sparse visuals.

**D. Make a genuine new story, not a reference remix.** Read stages 02–03. Explore at least five *different editorial approaches* (they differ in perspective, scale, structure, voice or visualization, not only in subject; five battles told the same way are one approach); select on substance, credible evidence, distinctive viewpoint, human relevance, an earned ending and compatibility with runtime. Study source documents for factual topics independent of reference videos, create claim/source ledger; separate fictional hypothesis from fact.

**Creative direction comes first** (read 10; it is the director's manual). In `40-plans/video-NN/direction.json`: the measured reference evidence, the five approaches and the chosen one with its runner-up, the episode strategy, and **two or three audiovisual treatments** (narrator, writing voice, pacing, visual language, sound, how picture and voice relate) each written out in three sample moments. Then one blind read of the treatments (`review-packet --kind treatment`, one fresh agent, `review-record`, every finding answered), your decision with reasons, and `direction-lock`, **before any script exists**. A later change re-locks with `--revise`; its answer lists what the change touched (`outdated_now`), and each piece is updated or kept on record with `direction-reapprove` before the stage that uses it continues (10 §3). Nothing here is a niche formula: two videos in one niche may need opposite treatments.

Then, from the locked treatment: `blueprint.json`, `beat-map.json` (each beat with its `experience`, `narration_direction`, `visual_intent`, `sound_direction` and `pace`; each `key_moment` with its `significance`: why it matters to this viewer, its reward, and what they must know first, given earlier through `depends_on` or `self_contained`; manual 10 §4), `script.json`, `editorial-review.md` (your own self-audit, with `writing_signals`), plus human-readable outline and title/thumbnail options. Each beat must move the story forward and be mapped to narration lines and a planned visual purpose. Do not pad or speed-read. **How the narration sounds and breathes is decided here, not at the audio stage.** It flows from the treatment and each beat's direction, read against the references' measured delivery.
- Each beat's `narration_direction` decides the performance for the writer: the narrator's attitude, the rhythm, whether the words alone carry it (they usually should). More expressive is not better (10 §4).
- The narration is planned as a performance before anything is paid for (05, "Narration as a performance"): at each important moment, how the line lands (`pause_landing`), whether a silence is needed and what it gives, what is seen and heard during it, and how the next line starts again (`pause_resume`). A delivery or pause cue is used wherever it gets a moment directly, with its scope stated (`cue_scope`: a cue colours the rest of its own line); the beat map marks `chapter_start`, so recording parts break only where the story starts a new chapter and a technical boundary never makes the narrator conclude or restart. Cue effects and the length forecast are bands from evidence (this voice's own `cue_observations` first), never one number per tag.
- Inline audio tags come from the whole catalogue (`STUDIO/data/elevenlabs-audio-tags.json`, read through 05). Every narration uses purposeful delivery and/or pause cues where the story calls for them (no quota, never decoration, never a fix for unclear writing); a script with none needs `tags_exception` with the user's approval (plan-check). Each kept tag gets its line under "Delivery and tags" in `editorial-review.md` (plan-check refuses one without).
- Silence is a tool, not an ingredient (03, 10 §5): the narrator's own rhythm comes first, and a held silence is planned only where the viewer needs time the voice does not give. A planned pause names the WHOLE silence wanted (`pause_total_s`, the voice's own gap included), how it is realised (`pause_via`: a tag or an edit hold, never both) and what it is for, what is seen and what is heard while it lasts (`pause_purpose`, `pause_picture`, `pause_sound`). Its length is a proposal: no quota, no formula, no length copied from a reference. Silence never makes the length (plan-check refuses it); the cold reader is shown every silence as the viewer would hear it.
- `text` holds only the spoken words and their tags: names the voice may say wrong go in `pronunciation.json`, team notes in a line's `note` (05).
- Each `content_flags` hit gets its line in `editorial-review.md`.

Then the **cold read**: `review-packet --kind script` (title, words and silences only, in a folder outside the run), then `review-read --kind script` (the reader as its own process confined to that folder; or ONE fresh agent of type `static-cold-reader` whose whole prompt is to read only that packet and follow it), `review-record`, and an answer to every finding (revised with its lines, kept if minor with why, disputed with why). The reader also names the developments that matter and, for each, what happened, why it matters from the words alone, what would be different without it and when the words gave its reason; `review-record` turns a gap into a finding (manual 06), so a reader who supplies the reason from their own knowledge, or gets it only afterwards on a key moment, still flags it. A major finding means revising and a fresh round-2 read by a new agent; after round 2 you decide, on record. Never write or soften a reviewer's findings. Run `plan-check --run "RUN" --video NN`; **do not buy TTS or pictures if it fails**. Fix the *story*, not just the numbers.

**E. Narration and production.** Read stages 04–05. Choose this video's narrator for its locked treatment (`voice-candidates`: five candidates described by character, register, age and accent; each preview's delivery is measured, because no agent here can listen; a preview's pace does not predict the real pace; Voice Design is priced first and billed only with `--execute`; the user may listen and overrule). `voice-pick --settings '{"stability":S,"similarity_boost":M}' --reason "..."` locks it for the video: voice, model and both settings, chosen for the narrator (stability is never a pace control: Eleven v4 has no speed setting). Videos of a series may share a voice; a change for a video is `voice-pick --replace` with a reason. Only `eleven_v4` / `eleven_v4_turbo` are used. When the voice, a setting, the tags or a name are in doubt, propose a short `narration-trial` (each question changes one thing; priced and shown to the user, recorded only after their approval, one take at a time inside the credit cap they authorised; the user gets the blind listening set, and no production setting changes until they have listened). ElevenLabs generations are paid, so the order is:
1. `tts ...` without `--execute`: the parts (they follow the beats), the characters and the credit forecast. The voice, model and settings come from the video's voice lock; a different value on the command line is refused.
2. `tts ... --max-parts 1 --execute`: the first real part *is* the calibration, paid once and kept. It reads the model's credits per character and the live balance first, and records what each request really cost (`logs/elevenlabs-ledger.jsonl`). The tool refuses more parts until the voice is measured.
3. `narration-measure`: the real pace (while speaking and overall), line gap, tag costs, and pauses next to the references', measured exactly as the references were; every line heard (a missed line is re-heard on its own window; still missing, it blocks until re-recorded or confirmed by the user's ear), no tag read aloud, the joins; and `delivery.json`, how the voice moves beat by beat next to what each beat asked for. A beat meant to lift that measures flat is rewritten in the parts not yet recorded.
4. `plan-check`: `real_forecast_s` inside the export window. If not, change the words of the parts not yet recorded; a hold may be shortened, never lengthened to reach the window. Never force pace with a delivery tag, a setting or by editing delivered audio. Then `holds`: each planned pause next to the gap the voice really left there (from the audio); listening previews for the user where a length is in doubt (`holds --preview Lnnn --totals a,b`); and `hold-decide --stage narration` for every pause whose lines are recorded (the whole silence, or `--no-hold`, and why), with its transition: how the voice goes into the silence and out of it (`clean` by default; a fade only on audible room tone, never on the voice) and what the bed does there, judged from how the line lands and the next begins (`holds`: `ending`), never applied by default.
5. The rest of the parts.

Continue only after the account, voice, model and charges are accepted. An edited line later re-records only the part that holds it (`--rerecord-changed`), and so does a part whose pronunciation or voice setup changed, or that was recorded before a direction change to the narrator, unless the narration is kept on record (`direction-reapprove --artifact narration`); a part to redo after listening is `--rerecord-parts N --reason`. **Partial, exhausted, missing or short narration is a BLOCKER.** `audio-check` must pass before stills and edit; it includes one voice setup throughout, every line heard, and narration plus planned holds inside the export window. Preserve partial chunks for resuming; never cut chapters to make a failed recording look done. Create an image style bible from the locked treatment's visual language and a shot plan from each beat's `visual_intent`, every shot saying what NEW thing its picture gives (`new_thing`); `shot-check` before any still is generated (it also lists near-identical prompts and long runs of one composition); generate stills with available OpenAI Images or the optional local image worker (both refuse a job until the direction, beat map and shot plan pass; each still names its shot and carries that shot's approved `frame_prompt`; `media-check` gives the same answer free, with the direction each still carries out), or prepare prompts for user-supplied stills (accepted on record with `direction-reapprove --artifact stills`). Add charts, maps, time lines, restrained illustration animation and on-screen text **when they improve comprehension**; do not turn every shot into a wallpaper slide or a frenetic montage. Optional instrumental music (the gated music worker: each track names the beats it scores) and sound design support the scene rather than bury it.

**F. CapCut and actual export.** First `narration-measure` on the complete narration, then `retime-shots`: every shot is timed to the real narration and its DECIDED holds (each adds only the difference between the whole silence decided and the voice's measured gap, inside that silence, verified in the file; it refuses while a planned pause is undecided, and seam holds restore the voice's gap at a join that holds no pause); with the stills made, each held silence is decided again with its picture (`hold-decide --stage picture`, retimed if its length changed), `edit-plan.json` names the one narration file the project carries (`narration_for_edit`, with its hash), and the edit plan carries the treatment's look and sound and each shot's beat direction, which the moves, joins and bed carry out (09). The project uses those times, never the plan's estimates, and that narration at 0 s, at speed 1, untrimmed. Use connected CapCut MCP/CLI as available to create a *real editable project*, no unsupported invented operations. Then the captions the user chose (05, 09): `captions-plan` (the script's words timed by the narration's own Whisper words, on the edit's timeline; the word box needs `--box-color` from this video's palette with `--box-color-why`), and, with CapCut closed, `captions-build --draft "<project>"`, then `capcut_tools.py capcut-repair --keep-text`; with captions off, no caption is built. Create `70-edit/video-NN/timeline.json` from the actual project (`capcut_draft`: the project folder; each clip's shot, picture file, beat and narrative purpose; every sound with its beats), then `timeline-check --run "RUN" --video NN` (it traces each clip back to its shot, still and beat, and reads the narration from the project itself: sped up, trimmed, cut or replaced is refused); listen at joins and watch the whole opening, chapter transitions and ending. A CapCut draft is **not** an exported file: export it yourself in CapCut on this PC with `capcut_desk.py` into `RUN/80-deliverables/video-NN/export/` (09, "Export and look": one small action, then a shot to look at, nothing clicked from memory; never a CapCut the user has open). Then bring its sound to the loudness the references are mastered at (`master-sound`, 05: one gain and a peak limiter, the picture copied untouched, the export kept) and run `export-check --run "RUN" --video NN --file "mastered.mp4" --deep` on that mastered file (it also finds the approved narration in the export, window by window), then the **final watch review** of that exact file: `av-profile --video NN --file` (its watch sheets), `review-packet --kind final --file` for ONE fresh agent who judges it against what each beat was meant to feel like and, as the script reader did, says for the developments that matter what happened, why it matters from the video alone, what would be different without it and when the video gave its reason; `review-record`, every finding answered; fix and re-export as needed (a new file gets its own read, whatever the round). The reviewer is not told what each part is meant to do: when you answer, compare its part-by-part account with each beat's `experience`, and treat a part that did not give what it was planned to as your own finding in the editorial review. `release-check` confirms every gate for that file. If CapCut cannot be used (the user has it open, or it fails), report the video as unverified; never claim to have watched a file not seen. No agent here can play video or hear audio: the sheets, transcripts and measurements are what is read, and the user is offered an optional watch.

**G. Critical pass before delivery.** Read stage 06. Evaluate title/thumbnail promise, originality, human interest, factual honesty, macro/micro pacing, viewer's mental participation, audio quality, shot-purpose/continuity, rhythm/breathing room, final satisfaction. Fix unearned hooks, repetitive middle, weak ending, historical anachronisms, bad compositions, robotic narration, frame/caption clutter and incomplete runtime. The goal is exceptional work, not a fictitious guaranteed “10/10” score. Use up to two research agents and up to three production agents when useful, with non-overlapping responsibilities, plus the three fresh readers (treatments, script, final cut: one agent each, holding only its packet); do not spawn a judge bureaucracy. A passed gate means the process happened, never that the video is good: say so in the report. Verify artifacts; communicate blockers plainly.

## Non-negotiables

- One purpose only: **new long-form YouTube videos built from narrated still images/graphics**. No other generation or editing modes, no unrelated prompts/assets, no reuse of source-video images or speech as final footage.
- Ref clips are **evidence about craft**, not license to reproduce another creator's words, distinctive footage, visual identity or unsupported factual claims. Preserve provenance; independent research for facts.
- Source and final frame timing matter. 2 fps (a frame every half second) is a broad coverage rate, **not literally every native frame**: a shot shorter than about a second, a flash or a quick insert can fall between samples. For a brief event, an exact transition or a possibly graphic moment, look closer at that stretch only (`inspect-window --ref V### --from mm:ss --to mm:ss`, a higher rate or `--native`); record the difference rather than falsely claiming every frame was viewed.
- Content: nothing a content review excluded is cited, adapted or brought back in other words or pictures (the direction, the script's content flags, the shot prompts and every generation job are checked against it), the final reviewer reads the export's shot sheets (every shot once) beside its watch sheets, and every picture the edit shows is looked at whole and recorded (`content-review --video NN --pictures --file looks.json`) before `timeline-check` passes. A war, a crime, an accident or a death can be the subject: the facts are told plainly and seriously, never in graphic form (02).
- Pictures: **nothing in a still is ever blurred, erased or covered** (the user, 2026-11-23); what would need hiding is kept out by the frame prompt and the still is made again; a picture the user supplies or a legitimate edit comes in recorded (`still_touchup.py --replace`, manual 04).
- Meaning: a viewer must be able to follow what happened and feel why the important developments matter, from the video alone. Key moments state their significance and what the viewer must know first, before the script; the readers keep what happened, why it matters and whether it paid apart; a gap is fixed at its cause (manual 10 §4, 06).
- The author is responsible for decisions. Machine checks measure objective properties, not taste or truth. No hard formula for hooks, number of chapters, humor frequency, zoom every few seconds or cliffhangers.
- Keep a progressing `RUN/todo.md`; use files as durable handoffs. Resume from what exists. Never run a Claude workflow. Never spend credits on a failed preflight. Final product is an actual CapCut project and its exported, verified video.
