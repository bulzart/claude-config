# 05 — Narration, sound and CapCut: build the actual long-form watch

## Voice is an actor, not an audiobook metronome

The narrator should sound like a person who understands and *cares* about the subject. Delivery must track what the viewer is discovering: animated when an insight is surprising, restrained when a human consequence lands, clear in explanations, conversational around ordinary examples. Vary phrasing and pauses naturally. Do not insert monotonous sentence-ending rises, repetitive emphases, forced inspirational intonation or a dramatic growl for every fact. The script is written natively for the target language, not word-for-word translation from an English draft. Dates, names, foreign places and uncommon terms are previewed and pronunciation-corrected.

A channel/run uses a consistent narrator persona and visual identity; different **videos** may have distinct emotional routes and spoken languages. One narrator may need more dynamic delivery for an inventive science topic than for reflective history. Pick voice/model only once when stable; if the voice cannot handle the language/topic, explain a necessary change.

## Inline audio tags: executing the story's own pauses, never inventing new ones

ElevenLabs v4/v4 Turbo read bracketed inline tags embedded directly in the sent text — not a fixed closed list, natural-language cues grouped roughly as emotion (`[whispers]`, `[sighs]`), pacing (`[slowly]`, `[rushed]`, `[snappy]`, `[speedy]`, `[drawn out]`) and pauses (`[pause]`, `[long pause]`, `[slightly pause]`). A tag carries forward until the next one — don't stack contrasting tags on the same words — and ordinary punctuation (ellipses, dashes, a capitalized word) already shapes pacing without needing a tag at all.

**Where a tag goes is decided by the story, not by whoever is running `tts`.** `03-duration-and-script.md`'s `beat-map.json` → `planned_silence_s` (or a passage `editorial-review.md` already flagged as a key moment — a quote, a turning point, the closing line) is the one legitimate source for "this line earns a real pause." Read those before writing a single tag; placing one anywhere else is inventing editorial weight the planning stage never decided, in the one stage of the pipeline that is supposed to only *execute*. Embed the tag directly inside the relevant line's `text` in `script.json` (e.g. `"text": "Retreat? Hell, we're not retreating. [pause] We're just attacking in a different direction."`) — it is sent exactly as written, no tool flag needed.

**`[long pause]` is reserved for moments that are genuinely pivotal** (a turning point, the final line) — not sprinkled for general gravity. `[pause]` suits a real beat inside a sentence (a quote's own turn, a declaration before its justification); `[slightly pause]` suits a smaller, still-real hitch. Most lines get no tag at all.

**Tags cost real, measurable time — budget for it, don't bolt it on after the script is already sized.** Confirmed by direct measurement: one `[long pause]` plus one `[slightly pause]` added just over 12 seconds to a single ~56-line, ~3,550-character chunk. Count tags into the word/time budget the same way `planned_silence_s` already does, *before* the final calibration pass (05's `--max-parts 1` step), not as a surprise discovered only after a full generation runs long.

## Pick the voice: five candidates, pace baked in from the start

Ported from `/analyze-with-loupe` Static mode, verified this session after the alternative (a generic voice plus a runtime delivery tag to force pace) failed twice on real paid generations. **A voice reads about as fast as the audio it was made from** — pace is a property of the voice itself, not something reliably imposed afterward.

1. `static_core.py voice-candidates --run "RUN" --video NN --count 5 [--search TEXT] [--design N] [--design-description "..."] [--design-text "..."]`: suggests up to 5 candidates — free from the account's existing voices (`--design 0`, the default) and/or billed ElevenLabs Voice Design (`--design N>0`). **Whichever source, the candidate's own sample must already speak at the niche's measured `pace_wpm`** (from `length-lock.json`): for Voice Design, say the pace in the description itself (e.g. `"...speaks at a brisk, measured pace, clearly and without rushing..."`), not as a tag applied later — a voice performs an untrained delivery style unreliably (ElevenLabs' own docs: outside the voice's sampled data "may be less reliable, and the result may not be optimal"), confirmed this session: two different runtime delivery tags each measured on-target on a short probe but made no measurable difference to two real full-length generations, both landing at the voice's unforced natural pace regardless of the tag. Each candidate's preview is downloaded, transcribed (Whisper) and measured with `wpm_from_transcript_raw` (pure speaking time, silence excluded) — the same yardstick used on the references. Listen to each (full paths given) and pick by ear.
2. `static_core.py voice-pick --run "RUN" --video NN --voice-id ID --name "..."`: locks one voice for the whole run. For a Voice-Design-sourced pick, this saves it to a permanent account voice first (`POST /v1/text-to-voice`) — a bare `generated_voice_id` is not otherwise usable for real TTS. One voice per run, every video and language; `--replace` to deliberately change it.
3. **Voice settings matter and are not optional.** Model-aware: eleven_v4 takes only `stability` and `similarity_boost` (confirmed via its own `GET /v1/models` capability flags, `can_use_style`/`can_use_speaker_boost` both false for this model — sending either is refused, not silently dropped). Never leave `--settings` empty: ElevenLabs' bare default `stability=0.5` "widens randomness/variability between generations," which reads as noise or inconsistency, especially on a Voice Design voice with no real human recording to anchor it. Raise `stability` (e.g. 0.6-0.7: steadier without flattening all expression) and set `similarity_boost` (e.g. 0.8: stay close to the designed character) to match the niche's register — grave/restrained wants more stability, playful/energetic can tolerate the default or lower.

## ElevenLabs process; hard stop on partial narration

1. **Preflight.** `plan-check` must pass. Run `static_core.py tts --run "RUN" --video NN --voice-id ID --model-id eleven_v4 --settings '{"stability":S,"similarity_boost":M}'` **without** `--execute`: displays all text chunks and total planned characters; make sure your account has sufficient credits. The script does not request or report your API key. Check the model's actual capability, cost and subscription balance with ElevenLabs before initiating billed calls. When `--execute` is chosen, it first requests subscription allowance (`GET /v1/user/subscription`) and checks the **entire ungenerated remainder plus 15% character reserve** before making the first billable call — a floor based on reported character allowance, **not a guarantee about credit conversion or model-specific cost**: this session, real billed usage ran consistently at ~40% of raw characters sent across four independent measurements, despite the model's documented `character_cost_multiplier` being 1.0 (unexplained — possibly a time-limited promotional rate; re-verify, never assume it still holds). Verify a ratio yourself from a call's own subscription before/after delta before using `--assume-cost-ratio` (0.1-1.0, default 1.0) to adjust the preflight's required balance — always auditable in the manifest, never guessed. An unavailable/insufficient balance stops before charges.
2. **Calibrate using the first real chunk, not a throwaway sample.** `static_core.py tts --run "RUN" --video NN --voice-id ID --model-id eleven_v4 --settings '...' --max-parts 1 --execute`: generates only the first chunk (same size a real chunk actually is, not a short artificial excerpt — a short sample's measured pace does not reliably predict a full ~8,000-character chunk's real behavior, confirmed this session), then stops (`mode: partial_by_design_max_parts`, nothing re-billed next time). **This paid chunk is not a throwaway** — transcribe it (Whisper) and measure `wpm_from_transcript_raw` against the locked `pace_wpm`; if it's close, keep going (re-run the same command without `--max-parts` to generate the rest — the finished chunk is kept, never re-billed). If the pace is off, do not reach for a delivery tag (it will not reliably transfer to the remaining chunks either) — redesign the voice (a new Voice Design candidate with different pace wording baked into the description) or revise the script's word count against the voice's real measured pace, *then* retry the first-chunk calibration again before committing to the rest.
3. **Produce the rest.** Repeat the same command (same voice/model/settings, no `--max-parts` or a higher one) after the first chunk calibrates well. The tool generates contiguous, line-indexed parts with previous/next text continuity hints; it maintains `50-audio/video-NN/manifest.json`, preserves successful chunks for resuming, and concatenates them to `narration.wav` only after all parts are done. Never put the key in JSON, the ZIP, logs, scripts or `CLAUDE.md`.
4. **Check.** Run `audio-check --run "RUN" --video NN`; it verifies all script lines represented, each audio part exists, a complete manifest, joined WAV and duration against locked target. An error, partial voice, credit cutoff, missing chunk, two-minute result for a ten-minute lock, or incomplete source line is **blocking**. Do not rush into images/CapCut using what exists. `plan-check`'s own `forecast_s` uses only the script's *planned* pauses (`pause_after_s`), which are never actually transmitted to ElevenLabs and do not predict its real natural inter-sentence breathing — trust `plan-check`'s `real_overhead_forecast_s` instead once `60-voice/voice-lock.json` has `measured_overhead_s`/`measured_overhead_lines` recorded (from the first-chunk calibration or a completed generation); fix the script word count against the voice's *real* measured pace if the generated duration genuinely differs, never stretch or edit the delivered audio to fit. A failed recording is *in progress*, not a shorter completed deliverable.
5. **Quality listen.** The duration and file checks cannot hear incorrect words, breaths, fake enthusiasm, unnatural joins, strange emphasis, noise or repetitive prosody. Listen to all joins, the first minute, turning points, foreign names and conclusion. Acknowledge that ElevenLabs does not guarantee deterministic output or exact duration from a character count. Re-record only necessary passages with approvals/credit accounting.

Supported backend: ElevenLabs `POST /v1/text-to-speech/:voice_id`, text/model ID, optional `previous_text` and `next_text`. Model limits vary; never make up a valid voice ID or assume a specific chosen model is accessible. The package intentionally leaves TTS `--execute` off by default so agents do not spend unexpectedly. Each output has an auditable status; a credit-exhausted partial result never becomes “final.”

## Music and layered sound

Use an instrumental bed when it suits the niche/story and adds value. For historical reflection, it may be almost subliminal; for an exciting reconstruction, use a gradual texture change around meaningful turns; for tutorials, clarity often beats score. Never drown speech. Distinguish neutral atmosphere, story-world sound, illustrative SFX, and musical punctuation. Silence can be an intentional dramatic tool. If using ACE-Step 1.5, ensure its environment exists and output is instrumental; validate duration, clipping, license and whether loops sound repetitive. Never fabricate unavailable sound layers. Keep an audible narration bed with consistent loudness across chapters and on small speakers.

## Editing into CapCut

The picture is generated as *clean stills*. Add editable captions, arrows, highlights, chapter cards, lower thirds, diagrams, labels, controlled zoom/crop, simple wipes and optional licensed overlays in CapCut **only when helpful**. Social media captions/badges/emoji are not defaults. No static rule requires constant movement; an image can hold when it carries thought. Resist transitions that create discontinuities; vary macro shot family because a narrative turns, not just because a timer expired.

Use the real connected CapCut MCP and CLI after discovering their actual available tool names and schema. Typical actions in the user's existing setup may include listing drafts, adding image/audio/text, creating tracks, setting segment properties, adding keyframes and transitions, reading timeline, validating and saving. Do **not** fabricate tool calls or assume there is a CapCut render/export API. When no CapCut export tool is accessible, produce a **valid editable CapCut project** and explicitly explain the manual export needed. If local CapCut CLI fails, use an available supported route or stop with a clear blocker; never call a JSON manifest an exported edit.

On this PC the project is written with `STUDIO/scripts/capcut_tools.py` next to the MCP and capcut-cli; its commands, their order and the files they read are in `STUDIO/reference/09-capcut-toolkit.md`.

Write `70-edit/video-NN/timeline.json` **derived from the actual CapCut timeline**, not a fictional plan, with `canvas` (e.g. `1920x1080`), `visual_segments` in chronological order, each `{ "start_s": ..., "end_s": ..., "asset_path": "...", "beat_id": "B01", "purpose": "..." }`, and an optional `audio_tracks` array, transitions, labels, note on project path and export status. No section should vanish because only enough pictures/audio were rendered for the opening. The actual last narrated beat and the final held frame must reach the locked story destination. Run:

```bash
python "$HOME/.claude/static-studio/scripts/static_core.py" timeline-check --run "RUN" --video 1
```

It checks contiguous visual range, beat links, story purposes, 16:9 canvas and successful audio gate; it does not substitute for playing through the project. Avoid black tails after the main edit and accidental CapCut “extra two seconds” tracks. A picture can intentionally lead/lag narration; the project duration should still respect the length contract.

## Export is a separate deliverable, with separate proof

Default YouTube landscape 1920×1080 or higher 16:9, 30 fps unless the project actually requires a deliberate alternative. For an accessible `output.mp4`:

```bash
python "$HOME/.claude/static-studio/scripts/static_core.py" export-check \
  --run "RUN" --video 1 --file "C:/path/to/output.mp4" --deep
```

The checker uses `ffprobe` for true exported duration, picture/audio stream presence, size and aspect, plus optional FFmpeg black/silence diagnostics. A diagnostic is a **clue**, not proof of an error (intentional silence/black may be right). Visually inspect opening, cuts, maps and chapter boundaries, listen to audio throughout, sample a few intervals in every chapter and watch the final minute. Verify exact titles/captions/names. Don't declare export verification complete when the file isn't accessible. Record export size, duration, settings and any unresolved issues in `80-deliverables/video-NN-release.md`.

## Publishing package

Provide a small set of title/thumbnail **concepts that truthfully promise the story**, not bait; a polished video description, source credits/licensing, optional chapter timestamps based on actual export, and a practical first-comment idea only if it contributes to discussion. Do not replicate the viral references' titles or thumbnails. YouTube Analytics may inform the next video later, but do not invent CTR, AVD or retention results for this one.
