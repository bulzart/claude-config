# 08 — Install and migrate without damaging the existing Claude Code setup

## What the command needs on this PC

`python`, `ffmpeg` and `ffprobe` in the shell where Claude Code runs; `faster-whisper` in that same Python environment (Whisper medium on the GPU, always; `static_core.py doctor --whisper` checks it, and the CPU runs only on the user's yes, as the command file says); and, for `av-profile` and `narration-measure`'s delivery measurement, `numpy`, `opencv-python`, `librosa`, `soundfile` and `Pillow` (`doctor` reports `av_profile_ready`). `ELEVENLABS_API_KEY` comes from the terminal's environment or a secret manager, never from a script on disk. FLUX 3 Image Klein (04), ACE-Step and the CapCut MCP/CLI are this PC's own installs: nothing here ships, reinstalls or replaces them. Nothing of another command is deleted or replaced: `/analyze-with-loupe`, its `awl-*` skills and older run folders belong to other work.

**Everything a run needs is in `STUDIO` or in the run.** The command file, the manuals, `STUDIO/scripts` (the director's kit, `director_kit.py`, among them: 04) and `STUDIO/data` are the whole reusable system; a run's own working scripts live in `RUN/workbench/`. Nothing a production needs is kept in a development or temporary folder: the first full film's makers were (2026-11-28), and the parts of them every film needs were installed as the kit, with the film's own scripts brought into its run. What lies outside both, by design: this PC's own installs named above, the memory guard and the two engine launchers (`Documents\AI\tools\memguard.py`, `flux3_python.cmd`, `acestep_python.cmd`), and the CapCut library and lock that `config.json` names (they belong to other toolkits on this PC). Reading a PDF source during research needs `pypdf` in the shell's Python (read untrusted files with `python -I`); nothing in `STUDIO/scripts` imports it.

**Writing files from the shell.** A long text, a JSON document or a script goes to disk with the file tool, never through a shell here-document: an odd number of apostrophes ends the here-document early, and a backslash in a Python string written that way becomes a control character in the file (a tracker and three answer files were hit, 2026-11-27 and 28).

## Sharing the GPU

FLUX 3 Image Klein, ACE-Step and Whisper jobs each take a GPU lease while they need the card, so the PC's other GPU users see them, and a program that keeps an idle model on the GPU lets it go while they need the memory. The lease is a file named `create-video-<kind>-<pid>` that says how long the job expects to hold the card (`expected_s`: FLUX 60 s plus 45 s per 1280x720 image, longer for a larger canvas; ACE-Step 90 s plus 3 s per second of music; Whisper 60 s plus its file's length divided by 6). Its folder is the PC's shared one (`~/.claude/create-clips/data/gpu`) only when that folder already exists, and nothing is created there; otherwise `static-studio/data/gpu`. `STATIC_GPU_LEASE_DIR` overrides it.

How long a job waits follows who holds the card, never one fixed time for every job: an earlier GPU job until it ends, or until it has run twice the time it declared (it is then treated as stuck; a holder that declares none, until its lease's time to live runs out); a program that keeps a Whisper model loaded on the card (it says so in `whisper.json` beside the leases) up to 75 s, since it looks every 10 s; memory held outside the leases only 15 s, unless it keeps coming back. Whisper waits only before its model loads. A job's `gpu_wait_s` only caps the wait; there is no default. First come, first served: a job waits only for leases taken before its own, so two jobs never wait for each other. Then the job goes ahead: a lease never changes the device, the model or the precision. The card's real size is read (nvidia-smi; this PC: an RTX 3060, 12,288 MB) and reported as `card_mb`; the memory guard's 16 GB caps the process memory of FLUX and ACE-Step (RAM and page file), not the card.
