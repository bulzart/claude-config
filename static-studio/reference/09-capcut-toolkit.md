# 09 — Writing the CapCut project on this PC (toolkit)

This manual is about **tools**, not about what the film should contain: what goes on the timeline stays decided by manuals 04 and 05. `STUDIO/scripts/capcut_tools.py` holds the CapCut-writing code this PC's CapCut 9.7 needs, so that a project opens with its clips linked, plays the moves and joins it was given, and can be exported. It works next to the CapCut MCP and capcut-cli, which still add the images, the narration, the music and the texts. `STUDIO/scripts/capcut_desk.py` then exports the finished project from CapCut's own window ("Export and look", below).

Call it as `python "$HOME/.claude/static-studio/scripts/capcut_tools.py" <command> ...` (`-h` on a command lists its options). Every call prints one JSON object on its last line. Exit 0 = done, 1 = a step failed (read `action`), 2 = refused (nothing was changed), 3 = CapCut is running.

## What this PC's CapCut needs (why these commands exist)

- **CapCut must be closed** for any write. Check before cloning with `tasklist /FI "IMAGENAME eq CapCut.exe" /NH` (what the commands do themselves); `capcut_read_timeline` also answers `capcutRunning`, and `capcut_list_drafts` a `locked` flag per draft. If it is open when the project is due, finish everything else, tell the user once to close it, and do not close it yourself. The commands refuse and change nothing.
- **Audio clips.** CapCut 9.x shows an audio clip only in its own form for a local file (type `extract_music`, named after its file). The MCP's `capcut_add_audio` writes type `audio`, which CapCut drops when it opens the project: every audio track showed empty (2026-11-22). `capcut-repair` puts every audio clip in CapCut's form first.
- **A project CapCut has opened is CapCut's.** CapCut rewrites a project in its own form when it opens it, and later edits written from outside do not stick. Open a project only when `timeline-check` passes; a fix found after that is made in a fresh project (`capcut-name`, then the order again).
- **Media links.** CapCut 9.7 opens a local clip through the `local_material_id` of its entry in the project's media list; without it every clip shows as missing. `capcut-repair` writes the entries and the links.
- **Moves.** CapCut 9.7 ignores the MCP's scale keyframes (a project keyed that way played every still static). `capcut-motion` writes the scale and position keyframes it does play, so use it for moves instead of `capcut_add_keyframe`.
- **The bed around a held silence.** The edit plan gives each decided pause's times on the edit's clock (`pauses[].times_in_edit`: `silence_from_s`, `silence_to_s`, `next_line_s`) and what the bed does there (`transition.bed`). Place a bed that `enters` so its clip starts inside that silence (`capcut_add_audio` at that time, with `capcut_add_audio_fade` for a gentle fade-in), one that `stops` so its clip ends there (a fade-out), one that `continues` across it, and none under a silence decided `none`; `timeline-check` checks those against `timeline.json`. A `dips` or `swells` move needs volume keyframes (`capcut_add_keyframe` with `KFTypeVolume`). Whether this PC's CapCut plays the MCP's volume keyframes is not verified (it ignores its scale keyframes), so check them in the export by listening, and prefer a clip boundary with a fade where that serves the same moment.
- **Transitions and text entrances** come only from the measured catalogue `STUDIO/data/capcut-catalogue.md`, which lists what this PC's CapCut really draws. This PC has no CapCut Pro and a project that holds a Pro option will not export, so a Pro option is refused too (`STUDIO/config.json` → `capcut.pro` is false). Use `capcut-transitions` for joins instead of `capcut_add_transition`.
- **Fonts.** A project shows a font only while the file stays where the project points. `capcut-font --list` gives each file's `kept_by`: CapCut's own folders are replaced when it updates and its cache may be cleared.
- Never `capcut lint --fix` (it copies every media file into the draft, shortens texts over 7 s, trims captions and closes gaps), and never `capcut_save` with `force`.

## The order

Steps 5 and 6 are only for what the edit has (moves, joins, fonts, text entrances): a project without them goes from step 4 to step 7.

1. `capcut-name --video NN` answers with a free project `name` (`DD_Mon_YYYY_vNN`, `-2`, `-3` when the folder exists) and its full `path`. That path is the `--draft` of every command below.
2. MCP `capcut_clone_draft {base: "_analyze-stack-template", newName: "<name>", empty: true}`: the empty template. Never edit or delete the template.
3. `capcut-prep --draft "<path>" --canvas 1920x1080` **immediately**, before any other call on the draft. It sets the template's identity files aside so the project can be registered, and sets the canvas (even edges).
4. MCP (the tool names are the ones this PC's CapCut MCP lists now; look them up first, as manual 05 says): `capcut_read_timeline` (the track indexes), `capcut_add_image` (`atSec` and `durSec` are each shot's `start_s` and length *after* `retime-shots` has timed `shot-plan.json` to the real narration, manual 05; never the planned estimates), `capcut_add_audio` (the narration at 0: the edit plan's `narration_for_edit.file`, at speed 1, untrimmed and never split; a music bed needs `capcut_add_track` type audio first and its `trackIndex`, else it lands on the narration's track and `capcut_validate` refuses the overlap), `capcut_add_text` as needed, `capcut_validate`, `capcut_save`. **This is the last MCP save**: the commands below write the project's files, and a later MCP save writes its own copy over them (then run them again).
5. Moves and joins: write the images file (below), then `capcut-motion --draft "<path>" --timeline FILE` and `capcut-transitions --draft "<path>" --timeline FILE`.
6. Texts: `capcut-font --list [--family NAME]`, then `capcut-font --draft "<path>" --font-file FILE [--track NAME]`. It sets the font on every text (or one track's) and writes the outline and box where CapCut 9.x draws them; read `font_missing_glyphs` (characters the font lacks; when it is not empty pick another font). Then `capcut-text-anim --draft "<path>" [--track NAME] --intro SLUG [--intro-duration S] [--outro SLUG]`: CapCut's own entrance on every text of the track, capped at each text's length. `capcut enums --text-intros` lists the slugs and `STUDIO/data/capcut-catalogue.md` says which this PC's CapCut draws and which are Pro; a refused slug is reported with its reason.
6b. Captions, when the user chose them (manual 05): `static_core.py captions-plan --run "RUN" --video NN` (after `retime-shots`; the word box adds `--box-color #RRGGBB --box-color-why "..."`), then `static_core.py captions-build --run "RUN" --video NN --draft "<path>"` (`--replace` builds them again). It writes the caption tracks with capcut-cli (`import-ass` for the highlight: one text per moment, the spoken word a yellow range; `import-srt` per word slot for the word box), puts every text at its planned time on the frame grid, sets the look's own font file from `STUDIO/fonts/` on every range with the outline where CapCut 9.x draws it, and reads the project back (`captions-check` repeats that read alone). Do not run `capcut-font` or `capcut-text-anim` on the caption tracks: the look is already complete and has no entrance animation. With captions off, nothing is built (a stray caption track is removed with `--replace`).
7. `capcut-repair --draft "<path>"`: every audio clip in CapCut's own form, register (identity, media list, store index), CapCut's own duration on every still added without one (a PNG has no duration, so a still added through the MCP is saved with none; CapCut writes 3 hours on a still it imports), the media links, `sync-timelines --nested` and `lint`, under the machine-wide store lock (it waits up to 15 minutes for another toolkit that holds it). Every text stays as it is. `ok: false` with an `action` means CapCut is running or lint found errors: fix through the MCP, `capcut_save`, then repeat steps 5–7. `--preview OUT.mp4` also renders capcut-cli's low-resolution proxy of the order, timing and text: a proxy, **never an export**.
8. Read the project back (`capcut_read_timeline` and the lint result), write `70-edit/video-NN/timeline.json` from it with `static_core.py timeline-write --run "RUN" --video NN --draft "<path>" [--sounds SOUNDS.json] [--extra NOTES.json]` (it traces each picture clip to its shot by its start and to its still, every sound to the narration, a recorded music bed or a sound named in SOUNDS.json with its beats, and lists what it cannot trace instead of guessing) (each clip's `shot_id` and the `asset_path` CapCut really shows; `capcut_draft`: this project's folder; the narration and every other sound under `audio_tracks`, a bed with the `beats` it serves) and run `static_core.py timeline-check`, as manual 05 says. With `capcut_draft` it reads the narration's segments from the project's own timeline document (file, where it sits, the stretch of the file it uses, speed): a narration sped up, trimmed, cut or replaced in CapCut is refused there.
9. Export and look (below), then the checks of the exported file (manual 05 and 06).

## The images file (for `capcut-motion` and `capcut-transitions`)

Write it from the edit plan (`70-edit/video-NN/edit-plan.json`: each shot's retimed `start_s` and its beat's `direction`, and the locked treatment's `direction` at the top), for example as `RUN/70-edit/video-NN/capcut-images.json`. Each still's move and transition carry out the locked treatment's visual language and its beat's `pace` and `visual_intent`: a held breath may stay still, a quickening beat may cut without a transition, a reveal may push in. Choose per moment, never one setting for the whole film:

```json
{"fps": 30, "images": [
  {"image": 1, "start": 0.0,  "motion": "zoom-in",   "amount": 0.06},
  {"image": 2, "start": 6.0,  "motion": "pan-right", "amount": 0.05, "transition": "mix", "trans_s": 0.5},
  {"image": 3, "start": 12.0, "motion": "custom", "scale": [1.0, 1.08], "x": [0.0, 0.03], "y": [0.0, 0.0]}
]}
```

- Every row needs `image`, `start` and `motion` (`none` for a clip that stays still); `amount`, `transition` and `trans_s` are optional. A clip with no row is left as it is.
- `image` is the clip's number in order. `start` is its start on the main track in seconds, the same `atSec` it was added at: a clip is found by its start (within half a frame), so these must be the starts the clips really have. `images_without_a_clip` in the answer must be empty.
- `motion` is `none`, `zoom-in`, `zoom-out`, `pan-left`, `pan-right`, `pan-up` or `pan-down`. `amount` is the zoom's change (0.06 = 6 %), or for a pan the scale it travels at. There is no default amount: without one nothing moves. `scale`, `x` and `y` together (all three) as `[at the start, at the end]` pairs replace the named motion (give `motion` any label then, such as `custom`): scale 1 = the picture covers the canvas, `x` and `y` = the picture's centre in half-canvas units (x to the right, y up). Keep a pan or a zoom inside the margin its scale gives, or the picture's edge shows.
- `transition` is a slug from `capcut enums --transitions` and plays into this image, on the clip before it, for `trans_s` seconds (default 0.5). `cut` or none = no transition. A refused slug is listed in `failed` with its reason.
- Both commands can run again: `capcut-motion` replaces its own keyframes, `capcut-transitions` keeps a clip that already has one.

## Drawn and animated explanations (manual 04)

CapCut has no freehand drawing primitive (only 9 fixed mask shapes, keyframes on an existing clip, and library stickers) — so a drawing is rendered as its own transparent-background clip and placed as an ordinary overlay:

1. Write a drawing spec JSON (one file per drawing): `{"canvas": "1920x1080", "fps": 30, "dur_s": <seconds>, "elements": [...]}`. The engine (2026-11-22; `draw_tool.py check` lists it): strokes `line`, `arrow`, `path` (`points`; `smooth` for a curve through them; `style` plain, ink, brush, pencil, chalk or marker; `dash` true, `[on, off]` in stroke widths or `"dot"`; `march` makes dashes run; `head` and `tail` open, filled, barb, dot or bar, the head riding the pen while it draws; `tip` a pen point), shapes `ellipse`, `rect`, `polygon` (a `style` for a hand-drawn outline, `radius` for rounded corners), `ring` (a hand-drawn loop), `mark` (`kind` tick or cross), `scribble`, `highlight` (a marker swipe), `redact` (a black bar), `hatch` (lines inside a polygon, drawn one by one), words `text` (`font` typed, hand, stencil, serif, sans, or `font_file`; entrances type, typewriter, decode, write, reveal, fade, pop, rise; `plate` a paper tag behind it; `underline`), `counter` (`from`, `to`, `prefix`, `suffix`, `decimals`: it counts over its entrance), `stamp` (stencil words in a border; `in.kind` slam), `card` (a paper card with `lines`, `pin` or `tape`; entrance drop, slide, flip, pop or fade), `pin`, `string` (`a` to `b`, sagging, a small swing as it lands), `travel` (an `icon` — plane, ship, envelope, tank, dot, chevron — moving along `points` over its entrance window, turning with the route, a `trail` behind it, `arrive_pulse`), `pulse` (rings, or radio arcs with `arc: [direction, spread]`, spreading while the entrance window lasts), `morse` (dots and dashes lit at `times`, seconds into the clip) and `group` (`children` moved as one). Any element takes `keys` (keyframes of `t`, `dx`, `dy`, `scale`, `rot`, `alpha`, `ease`), `rotate`, `pivot`, `shadow`, `glow`, `boil` (a hand-drawn jitter) and an `out` (fade, undraw, shrink); eases linear, in, out, inout, out3, expo, sine, back, inback, elastic, bounce. Each element's geometry (`points` for line/arrow/polygon, `center`+`w`+`h` for ellipse/rect, `at` for text — all coordinates fractions of the frame 0-1, sizes fractions of the short side), `stroke`/`fill` (hex) and `width`/`fill_alpha`, and an `in` entrance: `{"kind": "draw"|"wipe"|"fade"|"grow"|"pop"|"type", "start_s": <seconds from the clip's own start>, "dur_s": <seconds>, "ease": "linear"|"in"|"out"|"inout"}` (`draw` reveals a line/arrow progressively along its path; `type` reveals text character by character; `wipe` on ellipse/rect takes `"from": "left"|"right"|"top"|"bottom"`). An optional `out` mirrors `in` for an exit. `z` orders overlapping elements (higher on top). `boil` (bool) adds a few pixels of frame-to-frame jitter for a hand-drawn look. When the drawing marks something on its still (a pillar, a label, a map drawn on blank paper), place it in fractions of the still itself and give the spec `"still_motion": {"scale": [s0, s1], "x": [x0, x1], "y": [y0, y1]}`: the still's move in the edit (the values the images file gives capcut-motion, linear over the clip); the renderer moves every position and size with the picture frame by frame, so the drawing stays on what it marks while the still keeps its move. `still_framing` (`{"scale": s, "x": dx, "y": dy}`, one framing for the whole clip; `"framing_applied": true` when the builder already applied it) is the older static form.
2. `python "$HOME/.claude/static-studio/scripts/draw_tool.py" render --spec <spec.json> --out <RUN/60-visuals/video-NN/drawings/DNN.mov>`: renders every frame with Pillow at three times the canvas and reduces it (smooth edges; `--supersample N` to change), composites each element on its own, writes a frame that repeats the previous one only once, and encodes with `qtrle` (alpha-preserving QuickTime Animation) in a `.mov`. Local work, no model, no credits. `draw_tool.py preview --spec <spec> --bg <the still> --times 1.2,3.5 --out <sheet.jpg>` composites chosen moments over the still as the edit frames it, for looking before placing; `draw_tool.py texts --spec <spec>` lists the words it shows with their sizes, places and times (timeline-check reads the same). Verify with `ffprobe` (`pix_fmt` should read an alpha-carrying format) and by extracting a frame to view before placing it — this tool's render is verified mechanically; CapCut's actual on-canvas compositing of the import is not, so view it once placed (step 4).
3. If the drawing's track doesn't exist yet: MCP `capcut_add_track {draft, type: "video", name: "draw1"}` (a further drawing on the same still can share the track or get `draw2`, etc.).
4. MCP `capcut_add_video {draft, file: "<the rendered .mov>", trackIndex: <draw track>, atSec: <the still's start_s; a drawing that follows its still's move starts with the still and lasts as long, the move's clock being the clip's; otherwise the still's start_s + the drawing's own start within it>, trackRenderIndex: <above the still>}`. `capcut_validate`, `capcut_save`. View the result (step 7 of "The order") to confirm the alpha composites correctly over the still and sits clear of the caption band — a drawing is local work, correct it and render again freely.

## Export and look: CapCut's own window (`capcut_desk.py`)

**The screen is shared.** This is the user's computer, often in use while a run works. Before taking the front: `capcut_desk.py idle --wait 1800 --at-least 120` waits for two quiet minutes, then `focus --when-idle 120` brings CapCut forward only if nobody has typed or moved the mouse since. A click, key or shot is refused while another program is in front, and the tool never names another program's window (its title can name the user's files). If the user comes back mid-export, stop and wait again; CapCut keeps rendering an export without the front.

When `timeline-check` passes, export the project yourself, in CapCut on this PC, and look at what you made. `STUDIO/scripts/capcut_desk.py` is the hands; you are the eyes: **one small action, then a shot to look at. Nothing is clicked from memory.** It takes this PC's mouse and keyboard for about a minute per video, so do it in one go and give the PC back.

Call it as `python "$HOME/.claude/static-studio/scripts/capcut_desk.py" <command>` (one JSON line each; exit 2 = refused, nothing done):

- `shot --out PNG [--region X,Y,W,H] [--scale 0.5]`: the screen (or a part) as a picture to open with Read. The process is DPI-aware, so a pixel of the shot is a pixel of the screen; the answer gives the way back (`x / scale + region x`): a point read off a half-size shot is doubled before a click.
- `click X Y [--double|--right]`, `key ctrl+a`, `type "text"`: refused unless CapCut is the window in front, and a click also unless the window on top at that point is CapCut's. Text is typed character by character; the clipboard is never used. Closing keys (Alt+F4, Ctrl+W) are refused: CapCut is closed with `app quit`.
- `windows [--capcut]`, `focus`: the visible windows (title, rectangle, process, which is in front); bring CapCut forward. CapCut is found by its process, never by a title.
- `app start | quit | status`: start CapCut and wait for its window; `quit` sends the normal close message (what its X does: CapCut saves its project itself), repeated until it is gone. Never killed. A CapCut already open that this tool did not start belongs to the user or another session: `start` refuses it and `quit` never closes it; wait until it is closed.
- `export-path --set DIR | --restore | --show`: the folder CapCut exports to (registry `HKCU\Software\Bytedance\CapCut\Modules\Export`, value `ExportPath`), which CapCut reads when it starts. Only while CapCut is closed: `--set` keeps the user's own value once, `--restore` writes it back.

The loop for one video:

1. `export-path --set "RUN/80-deliverables/video-NN/export"`, `app start`, a shot. An advert ("CapCut Pro") is closed with its X, never Purchase or Subscribe.
2. Find the project's tile on the home page by the name under it (the newest comes first), click it, wait out the loading notice, and take a shot: the project's name in the title bar, and every track there (the stills, the drawings, the captions, the narration, the beds, the sounds). A missing track is a fault of the build, never fixed by hand in CapCut: quit, fix it in the toolkit, build a fresh project.
3. Export (top right), a shot: the file name (the video's slug, typed after Ctrl+A in the name field), 1080P, 30fps, H.264, mp4, and "Remove watermark" off (a Pro option this PC does not have). The toggle settles a moment after the dialog opens: read it on the second shot. Then the dialog's Export.
4. A shot every 10 to 30 s until it says the video is saved, then Close, never Share. The dialog moves between exports: read Close off the shot.
5. `app quit`, then `export-path --restore`. The PC is the user's again.

Then bring its sound to the level the references play at (`master-sound`, manual 05: one gain and a peak limiter, the picture copied untouched, the export kept), and check the mastered file with ffmpeg and the toolkit, not in CapCut: `export-check --deep` (length, size, frame rate, the approved narration found in the export window by window, black frames, silences), frames pulled at the moments that matter and looked at whole (the opening, each drawing, the captions of a line whose words had no time of their own, the ending), the bed measured around the held silences, then the final watch review (manual 06) and `release-check` on that exact file. A fault in the file is fixed in the toolkit and the run, built as a fresh project and exported again; the earlier file goes to `export/superseded/`, named for what was wrong with it.

## Not covered

Adding plain overlay clips (not a rendered drawing — see above), effects and caption tracks other than the chosen captions (step 6b) is not part of this toolkit: use the MCP and capcut-cli as manual 05 says (`capcut_add_text` for a text). `capcut-font`, `capcut-text-anim` and `capcut-repair` then work on whatever texts and clips they find. The video is exported only in CapCut's own window (above); capcut-cli's `--preview` is a proxy, never an export.
