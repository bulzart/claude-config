# 09 — Writing the CapCut project on this PC (toolkit)

This manual is about **tools**, not about what the film should contain: what goes on the timeline stays decided by manuals 04 and 05. `STUDIO/scripts/capcut_tools.py` holds the CapCut-writing code this PC's CapCut 9.7 needs, so that a project opens with its clips linked, plays the moves and joins it was given, and can be exported. Its `capcut-build` writes a video's whole project in one command, from the run's decided files, through the CapCut MCP's own library (`STUDIO/scripts/capcut_build.mjs` loads it from `STUDIO/config.json` → `capcut.mcp_core`). The MCP's tools, one call at a time, are the fallback; capcut-cli writes the joins and the captions. `STUDIO/scripts/capcut_desk.py` then exports the finished project from CapCut's own window ("Export and look", below).

Call it as `python "$HOME/.claude/static-studio/scripts/capcut_tools.py" <command> ...` (`-h` on a command lists its options). Every call prints one JSON object on its last line. Exit 0 = done, 1 = a step failed (read `action`), 2 = refused (nothing was changed), 3 = CapCut is running.

## What this PC's CapCut needs (why these commands exist)

- **CapCut must be closed** for any write. Check before cloning with `tasklist /FI "IMAGENAME eq CapCut.exe" /NH` (what the commands do themselves); `capcut_read_timeline` also answers `capcutRunning`, and `capcut_list_drafts` a `locked` flag per draft. If it is open when the project is due, finish everything else, tell the user once to close it, and do not close it yourself. The commands refuse and change nothing.
- **The project store is shared with the PC's other CapCut users.** The write commands (`capcut-prep`, `capcut-build`, `capcut-repair`, `capcut-font`, `capcut-motion`, `capcut-transitions`, `capcut-text-anim`) refuse while another pipeline holds a live lease on the store in the PC's shared lease folder (manual 08: `capcut-build-*` or `capcut-export`; exit 3, nothing changed): wait until it ends, then run the command again. `capcut-build` holds `capcut-build-create-video-<pid>` while it writes (taken under the shared desk lock, `capcut-desk.lock`), so another pipeline's GUI export waits for it, and `capcut_desk.py app start` refuses while another pipeline's `capcut-build-*` lease is live.
- **Audio clips.** CapCut 9.x shows an audio clip only in its own form for a local file (type `extract_music`, named after its file). The MCP's `capcut_add_audio` writes type `audio`, which CapCut drops when it opens the project: every audio track showed empty (2026-11-22). `capcut-build` writes every audio clip in that form, and `capcut-repair` puts any other one in it first.
- **A project CapCut has opened is CapCut's.** CapCut rewrites a project in its own form when it opens it, and later edits written from outside do not stick. Open a project only when `timeline-check` passes; a fix found after that is made in a fresh project (`capcut-name`, then the order again).
- **Media links.** CapCut 9.7 opens a local clip through the `local_material_id` of its entry in the project's media list; without it every clip shows as missing. `capcut-repair` writes the entries and the links.
- **Moves.** CapCut 9.7 ignores the MCP's scale keyframes (a project keyed that way played every still static). `capcut-motion` writes the scale and position keyframes it does play, so use it for moves instead of `capcut_add_keyframe`.
- **The bed around a held silence.** The edit plan gives each decided pause's times on the edit's clock (`pauses[].times_in_edit`: `silence_from_s`, `silence_to_s`, `next_line_s`) and what the bed does there (`transition.bed`). Place a bed that `enters` so its clip starts inside that silence (its `at` in the sound placements file, below, with a gentle fade-in), one that `stops` so its clip ends there (its `end`, with a fade-out), one that `continues` across it, and none under a silence decided `none`. `capcut-build` lists a held silence where the placed beds do not do what was decided; `timeline-check` checks the built project against `timeline.json`. A `dips` or `swells` move needs volume keyframes (`capcut_add_keyframe` with `KFTypeVolume`, after the build: "Fallback", below). Whether this PC's CapCut plays the MCP's volume keyframes is not verified (it ignores its scale keyframes), so check them in the export by listening, and prefer a clip boundary with a fade where that serves the same moment.
- **Transitions and text entrances** come only from the measured catalogue `STUDIO/data/capcut-catalogue.md`, which lists what this PC's CapCut really draws. This PC has no CapCut Pro and a project that holds a Pro option will not export, so a Pro option is refused too (`STUDIO/config.json` → `capcut.pro` is false). Use `capcut-transitions` for joins instead of `capcut_add_transition`.
- **Fonts.** A project shows a font only while the file stays where the project points. `capcut-font --list` gives each file's `kept_by`: CapCut's own folders are replaced when it updates and its cache may be cleared.
- Never `capcut lint --fix` (it copies every media file into the draft, shortens texts over 7 s, trims captions and closes gaps), and never `capcut_save` with `force`.

## The order

Step 5 is only for texts added by hand, and step 6 only when the user chose captions.

1. `capcut-name --video NN` answers with a free project `name` (`DD_Mon_YYYY_vNN`, `-2`, `-3` when the folder exists or CapCut's project list still names it: a folder deleted outside CapCut leaves its entry, and re-using the name shows two tiles for one folder) and its full `path`. That path is the `--draft` of every command below.
2. MCP `capcut_clone_draft {base: "_analyze-stack-template", newName: "<name>", empty: true}`: the empty template. Never edit or delete the template.
3. `capcut-prep --draft "<path>" --canvas 1920x1080` **immediately**, before any other call on the draft. It sets the template's identity files aside so the project can be registered, and sets the canvas (even edges).
4. `capcut-build --run "RUN" --video NN --draft "<path>"`: the whole project in one command ("capcut-build", below). An interrupted build is safe to recover from: the project is saved in one step (a temporary file renamed into place), so it is the fresh clone or the whole build, never half-written; a rerun on a built project is refused with nothing written (start again from `capcut-name`), and the lease and lock of a build whose process is gone are taken over at once. Every drawing it places has its render record beside it (`DNN.render-record.json`, "Drawn and animated explanations" below), and a stale render (its spec, still or clip changed since it was rendered) is refused: render it again. Run it with `--dry-run` first (the draft may be left out then): it checks every input and writes the build plan, and touches no project; read its `warnings`. The build adds every still, drawing and sound in one Node process through the CapCut MCP's own library, saves once, and then runs `capcut-motion` and `capcut-transitions` on the same draft with the images file. Each of those two can run again on its own (`--draft "<path>" --timeline <the images file>`): `capcut-motion` replaces its own keyframes, `capcut-transitions` keeps a clip that already has a join. A build is never repeated on the same draft: a changed input means a fresh project (steps 1–4).
5. Texts added by hand (`capcut_add_text`, "Fallback" below): `capcut-font --list [--family NAME]`, then `capcut-font --draft "<path>" --font-file FILE [--track NAME]`. It sets the font on every text (or one track's) and writes the outline and box where CapCut 9.x draws them; read `font_missing_glyphs` (characters the font lacks; when it is not empty pick another font). Then `capcut-text-anim --draft "<path>" [--track NAME] --intro SLUG [--intro-duration S] [--outro SLUG]`: CapCut's own entrance on every text of the track, capped at each text's length. `capcut enums --text-intros` lists the slugs and `STUDIO/data/capcut-catalogue.md` says which this PC's CapCut draws and which are Pro; a refused slug is reported with its reason.
6. Captions, when the user chose them (manual 05): `static_core.py captions-plan --run "RUN" --video NN` (after `retime-shots`; the word box adds `--box-color #RRGGBB --box-color-why "..."`), then `static_core.py captions-build --run "RUN" --video NN --draft "<path>"` (`--replace` builds them again). It writes the caption tracks with capcut-cli (`import-ass` for the highlight: one text per moment, the spoken word a yellow range; `import-srt` per word slot for the word box), puts every text at its planned time on the frame grid, sets the look's own font file from `STUDIO/fonts/` on every range with the outline where CapCut 9.x draws it, and reads the project back (`captions-check` repeats that read alone). Do not run `capcut-font` or `capcut-text-anim` on the caption tracks: the look is already complete and has no entrance animation. With captions off, nothing is built (a stray caption track is removed with `--replace`).
7. `capcut-repair --draft "<path>" --keep-text`: every audio clip in CapCut's own form, register (identity, media list, store index), CapCut's own duration on every still added without one (a PNG has no duration, so a still added through the MCP is saved with none; CapCut writes 3 hours on a still it imports), the media links, `sync-timelines --nested` and `lint`, under the machine-wide store lock (it waits up to 15 minutes for another toolkit that holds it). Every text stays as it is. `ok: false` with an `action` means CapCut is running or lint found errors: close CapCut and run it again, or fix what lint names at its cause in the run's files and build a fresh project (steps 1–4). `--preview OUT.mp4` also renders capcut-cli's low-resolution proxy of the order, timing and text: a proxy, **never an export**.
8. Read the project back (`capcut_read_timeline` after `capcut_discard`, so the MCP reads it from disk, and the lint result), write `70-edit/video-NN/timeline.json` from it with `static_core.py timeline-write --run "RUN" --video NN --draft "<path>" --sounds "RUN/70-edit/video-NN/capcut/sounds.json" [--extra NOTES.json]` (it traces each picture clip to its shot by its start, within one frame since CapCut snaps a clip to its frame grid when it saves, and to its still, every sound to the narration, a recorded music bed or a sound named in the sounds file `capcut-build` wrote, with its beats, and lists what it cannot trace instead of guessing) (each clip's `shot_id` and the `asset_path` CapCut really shows; `capcut_draft`: this project's folder; the narration and every other sound under `audio_tracks`, a bed with the `beats` it serves) and run `static_core.py timeline-check`, as manual 05 says: it refuses a `timeline.json` that no longer matches the saved project (`timeline-write` again), and when it passes it records the saved project as it shows (`70-edit/video-NN/timeline-check.json`: the pictures, overlays, every sound clip with its speed and volume, the texts, the canvas, the fps and the media fingerprints). `export-check` holds the export to that project: one changed since its check is refused. With `capcut_draft` it reads the narration's segments from the project's own timeline document (file, where it sits, the stretch of the file it uses, speed): a narration sped up, trimmed, cut or replaced in CapCut is refused there.
9. Export and look (below), then the checks of the exported file (manual 05 and 06).

## capcut-build: the whole project from the run's files

`capcut-build` decides nothing. Every time, file, move, level and bed comes from a file the run already holds, and the build places exactly that. It reads:

- **The edit plan** (`RUN/70-edit/video-NN/edit-plan.json`, written by `retime-shots`): each shot's `start_s` and `end_s` on the edit's clock, the held silences (`pauses`, with the bed decided for each), the beats, and the one narration file (`narration_for_edit`, with its sha256).
- **Each shot's still**: `RUN/60-visuals/video-NN/stills/<shot>.png`, or the still of the shot a callback `reuses` (`shot-plan.json`), the file `timeline-write` traces each clip to. A still `stills-provenance.json` records is checked against its record: made for that shot, and unchanged since the generator wrote it.
- **The images file** (below): each still's move and join, `RUN/70-edit/video-NN/capcut-images.json`. `--images FILE` names another file; `--no-moves` says the edit has none (every still holds, every join is a cut).
- **The drawings**: every rendered `DNN.mov` in `RUN/60-visuals/video-NN/drawings/`, with its spec `DNN.json` beside it naming the shot it is drawn on (`"shot": "S010"`). Each is placed from its still's start for as long as the still lasts (a shorter clip for its own length) on `draw1`, or `draw2` when two overlap. A drawing left out of the cut is moved out of the folder; other files there (a working note, a render record) are not read. `--drawings DIR` names another folder; `--no-drawings` places none.
- **The sound placements file** (below): the beds and sound effects as decided. `--sound-placements FILE` names another file; `--no-sounds` says the edit has neither.

Where it puts them: the stills on the first video track, in shot order, at their real times; the drawings on their own tracks above them (a drawing clip plays no sound); the narration on the first audio track at 0 s, at speed 1, untrimmed, from the start of its file to the end, in CapCut's own audio form (`extract_music`, as every audio clip); the beds on `music` (`music-2` when two overlap) and the sound effects on `sfx`. Then one `capcut_validate` and one save, then `capcut-motion` and `capcut-transitions`, then it reads the saved project back and counts every planned clip there.

It refuses (exit 2, nothing written) when an input is missing or unreadable; when a file differs from what its record says (the narration's sha256 in the edit plan, a still's in `stills-provenance.json`, a sound's `sha256` when the placements give one, a drawing's render record: its spec, still or clip changed since it was rendered); and when two decided files disagree: an images row that starts off its clip (the file was written for another timing), a join without the row of the image before it, a join the measured catalogue refuses, a drawing on a shot the edit plan does not have, a sound without the beats it serves, one longer than its file, one that ends after the last picture (the export would end on black). It writes only into a fresh, prepared clone (steps 1–3): never the template, a project that already holds a clip, a clone `capcut-prep` has not prepared, one CapCut has opened (`template-2.tmp` in it), or a canvas that is not YouTube 16:9. CapCut must be closed (exit 3). The machine-wide store lock is held while it writes the draft.

It lists, and never refuses: a still without a record, drawings rendered before render records existed (one warning), a drawing shorter or longer than its still, a drawing that does not follow its still's move as the images file has it, a held silence where the placed beds do not do what was decided, a clip volume other than 1, a bed without a music record, a sound outside the beats it names, a gap between two shots.

It writes, in `RUN/70-edit/video-NN/capcut/`: `build-plan.json` (every clip with its file, sha256, times and track: exactly what the Node process places), `sounds.json` (the sound effects, and any bed without a music record, by file name, for `timeline-write --sounds`), and after a real build `build-log.json`: the draft, every input with its sha256, what each track holds in the saved project, each step's answer, and the toolkit's version (`capcut_tools.py`, `capcut_build.mjs` and `core.js` by sha256, and Node's version). The log of an earlier project is kept beside it as `build-log.<project>.json`.

## The sound placements file (for `capcut-build`)

`RUN/70-edit/video-NN/sound-placements.json` holds every bed and sound effect as decided (manual 05, "Music and layered sound"):

```json
{"beds": [
  {"id": "M1", "file": "70-edit/video-01/music/baked/M1-lisbon.bed-m28.2dB.wav", "at": 28.84, "beats": ["B01", "B02"],
   "why": "enters inside the reveal silence"}
 ],
 "sfx": [
  {"id": "radio-call", "file": "50-audio/sfx/video-01/radio-call.bed-m14.9dB.wav", "at": 433.07, "beats": ["B08"],
   "purpose": "the 3 a.m. call, inside the silence after the line"}
 ]}
```

- Every item needs `file` (absolute, or relative to the run folder), `at` (where it starts on the edit's clock, in seconds) and `beats` (the beats it serves; `timeline-check` reads them). Optional: `end` (where it stops on the edit's clock; default the end of its file), `src_start` (where in the file it begins; default 0), `volume` (default 1), `fade_in` and `fade_out` (CapCut's own audio fades, in seconds), `kind` (for a bed `music`, `ambience` or `bed`; default `music` for a bed, `sfx` for a sound) and `sha256` (checked when given). `id`, `why` and `purpose` are notes; a sound's `purpose` goes to `timeline-write`.
- **The level lives in the file.** CapCut's export was measured ignoring a clip's volume (2026-11-22, a video clip), so each bed's and sound's level, its stretch and its fades are baked into a copy: `static_core.py bed-levels --plan PLAN.json --bake "RUN/70-edit/video-NN/music/baked" --run "RUN" --video NN` (PLAN: `{"narration": <the narration_for_edit file>, "tracks": [{"id", "file", "under_speech_db", "why", "src_start", "dur", "fade_in", "fade_out"}]}`, the dB under the voice chosen per track as manual 05 says). Place the baked copy from its start, at volume 1, with no fades of its own; a recorded bed's baked copy keeps the bed's music record. A stretch carries its place in the file in its name (`M2-letters.bed-m6.2dB.from20s-11.5s.wav`), so two stretches of one bed at one level stay two files; a sound in another container (an `.mp3`) is baked to a `.wav` copy.
- Times follow the story: `static_core.py sound-anchors --run "RUN" --video NN --file "<this file>" --list beds --to-anchors` (then `--list sfx`) ties each `at` and `end` to its narration landmark; after a re-recording, a new hold or a retime, `--resolve` (once per list) moves them before the build.
- A bed ends where its moment ends (`end`); two beds that overlap on purpose go on two tracks by themselves.

## The images file (for `capcut-build`, `capcut-motion` and `capcut-transitions`)

Write it from the edit plan (`70-edit/video-NN/edit-plan.json`: each shot's retimed `start_s` and its beat's `direction`, and the locked treatment's `direction` at the top), as `RUN/70-edit/video-NN/capcut-images.json` (where `capcut-build` reads it). Each still's move and transition carry out the locked treatment's visual language and its beat's `pace` and `visual_intent`: a held breath may stay still, a quickening beat may cut without a transition, a reveal may push in. Choose per moment, never one setting for the whole film:

```json
{"fps": 30, "images": [
  {"image": 1, "start": 0.0,  "motion": "zoom-in",   "amount": 0.06},
  {"image": 2, "start": 6.0,  "motion": "pan-right", "amount": 0.05, "transition": "mix", "trans_s": 0.5},
  {"image": 3, "start": 12.0, "motion": "custom", "scale": [1.0, 1.08], "x": [0.0, 0.03], "y": [0.0, 0.0]}
]}
```

- Every row needs `image`, `start` and `motion` (`none` for a clip that stays still); `amount`, `transition` and `trans_s` are optional. A clip with no row is left as it is.
- `image` is the clip's number in order. `start` is its start on the main track in seconds, its shot's retimed `start_s`: a clip is found by its start (within half a frame), so these must be the starts the clips really have (`capcut-build` refuses a row that is not). `images_without_a_clip` in the answer must be empty.
- `motion` is `none`, `zoom-in`, `zoom-out`, `pan-left`, `pan-right`, `pan-up` or `pan-down`. `amount` is the zoom's change (0.06 = 6 %), or for a pan the scale it travels at. There is no default amount: without one nothing moves. `scale`, `x` and `y` together (all three) as `[at the start, at the end]` pairs replace the named motion (give `motion` any label then, such as `custom`): scale 1 = the picture covers the canvas, `x` and `y` = the picture's centre in half-canvas units (x to the right, y up). Keep a pan or a zoom inside the margin its scale gives, or the picture's edge shows.
- `transition` is a slug from `capcut enums --transitions` and plays into this image, on the clip before it, for `trans_s` seconds (default 0.5). That clip is found by the row before it in the file, so that row is the previous image's. `cut` or none = no transition. A refused slug is listed in `failed` with its reason.
- Both commands can run again: `capcut-motion` replaces its own keyframes, `capcut-transitions` keeps a clip that already has one.

## Drawn and animated explanations (manual 04)

CapCut has no freehand drawing primitive (only 9 fixed mask shapes, keyframes on an existing clip, and library stickers) — so a drawing is rendered as its own transparent-background clip and placed as an ordinary overlay:

1. Write a drawing spec JSON (one file per drawing): `{"canvas": "1920x1080", "fps": 30, "dur_s": <seconds>, "shot": "<the shot whose still it is drawn on>", "elements": [...]}`. The engine (2026-11-22; `draw_tool.py check` lists it): strokes `line`, `arrow`, `path` (`points`; `smooth` for a curve through them; `style` plain, ink, brush, pencil, chalk or marker; `dash` true, `[on, off]` in stroke widths or `"dot"`; `march` makes dashes run; `head` and `tail` open, filled, barb, dot or bar, the head riding the pen while it draws; `tip` a pen point), shapes `ellipse`, `rect`, `polygon` (a `style` for a hand-drawn outline, `radius` for rounded corners), `ring` (a hand-drawn loop), `mark` (`kind` tick or cross), `scribble`, `highlight` (a marker swipe), `redact` (a black bar), `hatch` (lines inside a polygon, drawn one by one), words `text` (`font` typed, hand, stencil, serif, sans, or `font_file`; entrances type, typewriter, decode, write, reveal, fade, pop, rise; `plate` a paper tag behind it; `underline`), `counter` (`from`, `to`, `prefix`, `suffix`, `decimals`, `step`: it counts over its entrance, lands exactly on `to` and moves a big count in round steps; end its window on the spoken number so it is there as it is said), `stamp` (stencil words in a border; `in.kind` slam), `card` (a paper card with `lines`, `pin` or `tape`; entrance drop, slide, flip, pop or fade), `pin`, `string` (`a` to `b`, sagging, a small swing as it lands), `travel` (an `icon` — plane, ship, envelope, tank, dot, chevron — moving along `points` over its entrance window, turning with the route, a `trail` behind it, `arrive_pulse`), `pulse` (rings, or radio arcs with `arc: [direction, spread]`, spreading while the entrance window lasts), `morse` (dots and dashes lit at `times`, seconds into the clip) and `group` (`children` moved as one). Any element takes `keys` (keyframes of `t`, `dx`, `dy`, `scale`, `rot`, `alpha`, `ease`), `rotate`, `pivot`, `shadow`, `glow`, `boil` (a hand-drawn jitter) and an `out` (fade, undraw, shrink); eases linear, in, out, inout, out3, expo, sine, back, inback, elastic, bounce. Each element's geometry (`points` for line/arrow/polygon, `center`+`w`+`h` for ellipse/rect, `at` for text — all coordinates fractions of the frame 0-1, sizes fractions of the short side), `stroke`/`fill` (hex) and `width`/`fill_alpha`, and an `in` entrance: `{"kind": "draw"|"wipe"|"fade"|"grow"|"pop"|"type", "start_s": <seconds from the clip's own start>, "dur_s": <seconds>, "ease": "linear"|"in"|"out"|"inout"}` (`draw` reveals a line/arrow progressively along its path; `type` reveals text character by character; `wipe` on ellipse/rect takes `"from": "left"|"right"|"top"|"bottom"`). An optional `out` mirrors `in` for an exit. `z` orders overlapping elements (higher on top). `boil` (bool) adds a few pixels of frame-to-frame jitter for a hand-drawn look. When the drawing marks something on its still (a pillar, a label, a map drawn on blank paper), place it in fractions of the still itself and give the spec `"still_motion": {"scale": [s0, s1], "x": [x0, x1], "y": [y0, y1]}`: the still's move in the edit (the values the images file gives capcut-motion, linear over the clip); the renderer moves every position and size with the picture frame by frame, so the drawing stays on what it marks while the still keeps its move. `still_framing` (`{"scale": s, "x": dx, "y": dy}`, one framing for the whole clip; `"framing_applied": true` when the builder already applied it) is the older static form.
2. `python "$HOME/.claude/static-studio/scripts/draw_tool.py" render --spec <spec.json> --out <RUN/60-visuals/video-NN/drawings/DNN.mov>`: renders every frame with Pillow at three times the canvas and reduces it (smooth edges; `--supersample N` to change), composites each element on its own, writes a frame that repeats the previous one only once, and encodes with `qtrle` (alpha-preserving QuickTime Animation) in a `.mov`. Local work, no model, no credits. A render that succeeds writes `DNN.render-record.json` beside the clip: the spec's sha256 (by its canonical content), the still and its sha256, the shot and beat, the clip's and the tool's sha256, the size, fps and duration, and the texts, counters and colours it shows; a failed render leaves none. `--still` names the still when needed (by default the shot's still, as `capcut-build` finds it). `draw_tool.py preview --spec <spec> --bg <the still> --times 1.2,3.5 --out <sheet.jpg>` composites chosen moments over the still as the edit frames it, for looking before placing; `draw_tool.py texts --spec <spec>` lists the words it shows with their sizes, places and times (timeline-check reads the same). Verify with `ffprobe` (`pix_fmt` should read an alpha-carrying format) and by extracting a frame to view before placing it — this tool's render is verified mechanically; CapCut's actual on-canvas compositing of the import is not, so view it once placed (step 4).
3. Leave the rendered `DNN.mov` beside its spec in `RUN/60-visuals/video-NN/drawings/`, the spec naming the shot it is drawn on (`"shot": "S010"`): `capcut-build` places it from that still's start for as long as the still lasts, on `draw1` above the stills (`draw2` when two drawings overlap). Render it for the shot's retimed length: the build lists a clip shorter or longer than its still, and one whose `still_motion` is not its still's move in the images file. It refuses a stale render, and `timeline-check` checks every drawing again (manual 04: a stale render, a counter's figure against its shot's words, the content rules, the locked palette).
4. View the built project (step 4 of "The order") to confirm the alpha composites correctly over the still and sits clear of the caption band — a drawing is local work: correct it, render it again and build a fresh project.

## Fallback: one MCP call at a time

When `capcut-build` cannot run here (Node or the MCP's library missing), the same project is made with the MCP's own tools after step 3 (the tool names are the ones this PC's CapCut MCP lists now; look them up first, as manual 05 says): `capcut_read_timeline` (the track indexes), `capcut_add_image` per still (`atSec` and `durSec` are each shot's `start_s` and length *after* `retime-shots` has timed `shot-plan.json` to the real narration, manual 05; never the planned estimates), `capcut_add_track` type video `draw1` and `capcut_add_video` per drawing (`atSec` its still's `start_s`, `trackRenderIndex` above the still), `capcut_add_audio` for the narration at 0 (the edit plan's `narration_for_edit.file`, at speed 1, untrimmed and never split), `capcut_add_track` type audio and `capcut_add_audio` per bed and sound (on the narration's track a bed overlaps it and `capcut_validate` refuses), `capcut_add_audio_fade` where a fade was decided, `capcut_add_text` as needed, `capcut_validate`, `capcut_save`. **This is the last MCP save**: then `capcut-motion` and `capcut-transitions` with the images file, and steps 5–8. A later MCP save writes its own copy over the project's files (then run those two again), and an MCP session that opened the draft before another command wrote it holds the old copy: `capcut_discard` it before any further call.

## Export and look: CapCut's own window (`capcut_desk.py`)

**The screen is shared.** This is the user's computer, often in use while a run works. Before taking the front: `capcut_desk.py idle --wait 1800 --at-least 120` waits for two quiet minutes, then `focus --when-idle 120` brings CapCut forward only if nobody has typed or moved the mouse since. A click, key or shot is refused while another program is in front, and the tool never names another program's window (its title can name the user's files). If the user comes back mid-export, stop and wait again; CapCut keeps rendering an export without the front.

When `timeline-check` passes, export the project yourself, in CapCut on this PC, and look at what you made. `STUDIO/scripts/capcut_desk.py` is the hands; you are the eyes: **one small action, then a shot to look at. Nothing is clicked from memory.** It takes this PC's mouse and keyboard for about a minute per video, so do it in one go and give the PC back.

Call it as `python "$HOME/.claude/static-studio/scripts/capcut_desk.py" <command>` (one JSON line each; exit 2 = refused, nothing done):

- `shot --out PNG [--region X,Y,W,H] [--scale 0.5]`: the screen (or a part) as a picture to open with Read. The process is DPI-aware, so a pixel of the shot is a pixel of the screen; the answer gives the way back (`x / scale + region x`): a point read off a half-size shot is doubled before a click.
- `click X Y [--double|--right]`, `key ctrl+a`, `type "text"`: refused unless CapCut is the window in front, and a click also unless the window on top at that point is CapCut's. Text is typed character by character; the clipboard is never used. Closing keys (Alt+F4, Ctrl+W) are refused: CapCut is closed with `app quit`.
- `windows [--capcut]`, `focus`: the visible windows (title, rectangle, process, which is in front); bring CapCut forward. CapCut is found by its process, never by a title.
- `app start | quit | status`: start CapCut and wait for its window; `quit` sends the normal close message (what its X does: CapCut saves its project itself), repeated until it is gone. Never killed. A CapCut already open that this tool did not start belongs to the user or another session: `start` refuses it and `quit` never closes it; wait until it is closed. A window is this tool's when its process was recorded at start or descends from one that was (CapCut opens windows in processes it spawns later); `quit` looks again for a few seconds before it refuses. `start` also refuses while a project is being written into the store (a live `capcut-build-*` lease, this pipeline's own included).
- `export-path --set DIR | --restore | --show`: the folder CapCut exports to (registry `HKCU\Software\Bytedance\CapCut\Modules\Export`, value `ExportPath`), which CapCut reads when it starts. Only while CapCut is closed: `--set` keeps the user's own value once, `--restore` writes it back.

The loop for one video:

1. `export-path --set "RUN/80-deliverables/video-NN/export"`, `app start`, a shot. An advert ("CapCut Pro") is closed with its X, never Purchase or Subscribe.
2. Find the project's tile on the home page by the name under it (the newest comes first), click it, wait out the loading notice, and take a shot: the project's name in the title bar, and every track there (the stills, the drawings, the captions, the narration, the beds, the sounds). A missing track is a fault of the build, never fixed by hand in CapCut: quit, fix it in the toolkit, build a fresh project.
3. Export (top right), a shot: the file name (the video's slug, typed after Ctrl+A in the name field), 1080P, 30fps, H.264, mp4, and "Remove watermark" off (a Pro option this PC does not have). The toggle settles a moment after the dialog opens: read it on the second shot. Then the dialog's Export.
4. A shot every 10 to 30 s until it says the video is saved, then Close, never Share. The dialog moves between exports: read Close off the shot.
5. `app quit`, then `export-path --restore`. The PC is the user's again.

Then bring its sound to the level the references play at (`master-sound`, manual 05: one gain and a peak limiter, the picture copied untouched, the export kept), and check the mastered file with ffmpeg and the toolkit, not in CapCut: `export-check --deep` (the run's exact size and frame rate; the project `timeline-check` recorded, unchanged since apart from CapCut's own frame snapping, and the export's length equal to it within 0.15 s; the approved narration found in windows that tile the whole film; black or silent stretches, which block unless the edit plan's held silences or `70-edit/video-NN/planned-blanks.json` hold them; the picture at each shot matched against the project's stills by keypoints; the file on record by its full sha256 in `export-provenance.json`), frames pulled at the moments that matter and looked at whole (the opening, each drawing, the captions of a line whose words had no time of their own, the ending), the bed measured around the held silences, then the final watch review (manual 06) and `release-check` on that exact file (it requires the file deep-checked with no issues, its project unchanged since, and the recorded master, never the unmastered export). A fault in the file is fixed in the toolkit and the run, built as a fresh project and exported again; the earlier file goes to `export/superseded/`, named for what was wrong with it.

## Not covered

Adding plain overlay clips (not a rendered drawing — see above), effects and caption tracks other than the chosen captions (step 6) is not part of this toolkit: use the MCP and capcut-cli as manual 05 says (`capcut_add_text` for a text; `capcut-build` adds none). `capcut-font`, `capcut-text-anim` and `capcut-repair` then work on whatever texts and clips they find. The video is exported only in CapCut's own window (above); capcut-cli's `--preview` is a proxy, never an export.
